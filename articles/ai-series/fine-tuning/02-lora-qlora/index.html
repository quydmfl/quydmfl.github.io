Bài 01 đo thật LoRA giảm 99.89% bộ nhớ optimizer/gradient so với full fine-tune, bằng cách chỉ train ~0.1% tham số qua thư viện peft. Nhưng bài đó dùng peft như hộp đen — chỉ đo hiệu quả, chưa biết bên trong LoRA làm gì. Bài này cài đúng cơ chế đó từ đầu, verify khớp peft, rồi đi thêm một bước: QLoRA — nén luôn cả phần model weights mà LoRA thường không đụng tới.

Cơ chế LoRA: đóng băng W gốc, học ΔW = B·A hạng thấp

Một linear layer bình thường tính h = Wx. Fine-tune đầy đủ nghĩa là cập nhật trực tiếp W. LoRA làm khác: đóng băng W (không cập nhật, không tính gradient), rồi cộng thêm một nhánh phụ:

h = Wx + BAx

A có shape (r, in_features), B có shape (out_features, r). r (rank) là một số nhỏ — bài này dùng r=8 — nhỏ hơn rất nhiều so với in_features/out_features (896 trong ví dụ dưới). Vì r << in, out, tổng số tham số của A cộng B (r*in + out*r) nhỏ hơn rất nhiều so với số tham số của W (in*out). Đây chính là toán học đứng sau con số 0.1094% ở bài 01.

Có một chi tiết init quan trọng: B được khởi tạo bằng 0 (A thì khởi tạo ngẫu nhiên, kiểu Kaiming, giống cách peft làm). Vì B = 0, tích BAx cũng bằng 0 bất kể A là gì — nên ngay lúc bắt đầu train, h = Wx + 0 = Wx, y hệt model gốc chưa có LoRA. Model pretrained không bị phá ngay từ step đầu; LoRA chỉ bắt đầu thay đổi hành vi model khi B được cập nhật qua các bước gradient descent tiếp theo.

Cài LoRALinear từ đầu

Code dưới bọc một nn.Linear đã đóng băng, cộng thêm nhánh A/B như công thức trên:

# lora_qlora_demo.py
"""Bài 02 - LoRA/QLoRA: cài LoRALinear từ đầu (đóng băng weight gốc, học 2 ma
trận A/B hạng thấp), verify khớp với peft.LoraConfig trên đúng 1 layer thật
lấy từ Qwen2.5-0.5B-Instruct. Sau đó QLoRA: quantize base model xuống 4-bit
(bitsandbytes), đo thật dung lượng giảm được."""
import copy
import torch
import torch.nn as nn
from transformers import AutoModelForCausalLM
from peft import LoraConfig, get_peft_model

torch.manual_seed(0)
MODEL_NAME = "Qwen/Qwen2.5-0.5B-Instruct"


class LoRALinear(nn.Module):
    """Bọc 1 nn.Linear đã đóng băng, cộng thêm nhánh low-rank A (r x in) và
    B (out x r) - chỉ A, B là trainable. B init = 0 nên lúc chưa train,
    LoRALinear cho output y hệt linear gốc (không phá model pretrained)."""

    def __init__(self, base_linear, r=8, alpha=16):
        super().__init__()
        self.base = base_linear
        for p in self.base.parameters():
            p.requires_grad = False
        in_f, out_f = base_linear.in_features, base_linear.out_features
        self.A = nn.Parameter(torch.zeros(r, in_f))
        self.B = nn.Parameter(torch.zeros(out_f, r))
        nn.init.kaiming_uniform_(self.A, a=5**0.5)
        self.scaling = alpha / r

    def forward(self, x):
        return self.base(x) + (x @ self.A.T @ self.B.T) * self.scaling


model = AutoModelForCausalLM.from_pretrained(MODEL_NAME, dtype=torch.float32)
target_layer = model.model.layers[0].self_attn.q_proj  # 1 Linear thật, kích thước thật
print(f"Layer thật lấy từ model: {target_layer}")

x = torch.randn(2, 5, target_layer.in_features)

# --- LoRALinear tự viết ---
custom_lora = LoRALinear(copy.deepcopy(target_layer), r=8, alpha=16)
with torch.no_grad():
    custom_lora.B.copy_(torch.randn_like(custom_lora.B) * 0.01)  # B khác 0 để so sánh có ý nghĩa
out_custom = custom_lora(x)

# --- peft LoraConfig áp lên đúng 1 Linear (bọc trong Sequential để peft xử lý được) ---
wrapped = nn.Sequential(copy.deepcopy(target_layer))
peft_wrapped = get_peft_model(
    wrapped, LoraConfig(r=8, lora_alpha=16, target_modules=["0"], lora_dropout=0.0)
)
peft_layer = peft_wrapped.base_model.model[0]
with torch.no_grad():
    peft_layer.lora_A["default"].weight.copy_(custom_lora.A)
    peft_layer.lora_B["default"].weight.copy_(custom_lora.B)
out_peft = peft_wrapped(x)

max_diff = (out_custom - out_peft).abs().max().item()
print(f"\nMax diff LoRALinear tự viết vs peft (cùng A/B): {max_diff:.3e}")
assert max_diff < 1e-5, "LoRALinear tự viết KHÔNG khớp peft"
print("OK: LoRALinear tự viết khớp peft.LoraConfig (sai số < 1e-5)")

# --- verify B=0 lúc init -> LoRA không đổi gì so với model gốc ---
fresh_lora = LoRALinear(copy.deepcopy(target_layer), r=8, alpha=16)
out_fresh = fresh_lora(x)
out_base = target_layer(x)
diff_init = (out_fresh - out_base).abs().max().item()
print(f"\nMax diff LoRA(B=0 lúc init) vs Linear gốc: {diff_init:.3e}")
assert diff_init < 1e-6, "B=0 lúc init phải cho output y hệt model gốc"
print("OK: LoRA lúc chưa train (B=0) không thay đổi hành vi model gốc")

# --- QLoRA: quantize base model xuống 4-bit, đo dung lượng thật ---
from transformers import BitsAndBytesConfig

fp32_bytes = sum(p.numel() * p.element_size() for p in model.parameters())
print(f"\nDung lượng model fp32: {fp32_bytes / 1e9:.3f} GB")

bnb_cfg = BitsAndBytesConfig(load_in_4bit=True, bnb_4bit_compute_dtype=torch.float16)
model_4bit = AutoModelForCausalLM.from_pretrained(MODEL_NAME, quantization_config=bnb_cfg)
q_bytes = sum(p.numel() * p.element_size() for p in model_4bit.parameters())
print(f"Dung lượng model 4-bit (QLoRA): {q_bytes / 1e9:.3f} GB")
reduction = (1 - q_bytes / fp32_bytes) * 100
print(f"Giảm {reduction:.1f}% dung lượng")

assert q_bytes < fp32_bytes / 3, "4-bit phải nhỏ hơn fp32 đáng kể (kỳ vọng ~4x)"
print(f"\nOK: quantize 4-bit giảm {reduction:.1f}% dung lượng model — LoRA adapter (nhỏ, fp32/fp16) "
      f"gắn lên trên base 4-bit này chính là QLoRA")

base_linear là layer thật lấy từ model, không phải nn.Linear toy tự tạo: model.model.layers[0].self_attn.q_proj — projection tính query của self-attention ở layer đầu tiên của Qwen2.5-0.5B-Instruct, kích thước thật 896x896. Forward pass của LoRALinear cộng thẳng output của base (linear gốc, đã đóng băng) với nhánh LoRA (x @ A.T @ B.T) * scaling — scaling = alpha / r là hệ số nhân theo đúng định nghĩa gốc của LoRA, kiểm soát mức ảnh hưởng của nhánh low-rank so với nhánh gốc.

Script bọc chính layer q_proj đó (một bản copy riêng) trong nn.Sequential, rồi cho peft.get_peft_model áp LoraConfig(r=8, lora_alpha=16, ...) lên. Sau khi copy đúng giá trị A/B từ LoRALinear tự viết sang lora_A/lora_B của peft, hai bên nhận cùng input và cho output sai khác đúng 0.000e+00 — không phải một số nhỏ gần 0, mà bằng 0 tuyệt đối, vì cả hai làm đúng cùng phép nhân ma trận trên cùng dữ liệu. Đây là bằng chứng cài đúng công thức chuẩn của LoRA, không phải một biến thể “tương tự”.

Tạo một LoRALinear mới, chưa hề chỉnh B (vẫn giữ giá trị init = 0), rồi so output với target_layer gốc trên cùng input x. Sai khác cũng bằng 0.000e+00 — khẳng định đúng thiết kế: gắn LoRA vào một model pretrained không làm thay đổi gì hành vi của nó cho tới khi training thật sự bắt đầu cập nhật B.

QLoRA: LoRA + quantize base model xuống 4-bit

Bài 01 đã chỉ ra: LoRA giảm được optimizer state và gradient buffer (99.89%), nhưng không giảm được model weights — base model vẫn phải load full để tính forward pass, vì Wx trong công thức h = Wx + BAx vẫn cần W đầy đủ, không bị đụng tới. QLoRA giải quyết đúng phần còn thiếu đó: nén W (base model) xuống 4-bit bằng quantization, còn A/B (LoRA adapter) vẫn giữ fp16/fp32 để giữ độ chính xác cần cho training.

BitsAndBytesConfig(load_in_4bit=True, bnb_4bit_compute_dtype=torch.float16) yêu cầu transformers load model với mỗi tham số nén xuống 4-bit khi lưu trong bộ nhớ, chỉ dequantize tạm về float16 lúc tính toán compute. Đo thật:

Dung lượng model fp32: 1.976 GB
Dung lượng model 4-bit (QLoRA): 0.451 GB
Giảm 77.2% dung lượng

OK: quantize 4-bit giảm 77.2% dung lượng model — LoRA adapter (nhỏ, fp32/fp16) gắn lên trên base 4-bit này chính là QLoRA

1.976 GB khớp đúng số đã đo ở bài 01 (fp32, cùng model). Sau quantize, model chỉ còn 0.451 GB — giảm 77.2%, tức tỷ lệ nén thực tế chỉ khoảng 4.4x (1.976 GB / 0.451 GB), thấp hơn hẳn tỷ lệ bit lý thuyết fp32 → 4-bit (8x). Lý do KHÔNG phải “một vài layer nhỏ vẫn giữ dtype gốc” — embedding/lm_head và layer norm không hề nhỏ. bitsandbytes chỉ quantize các lớp Linear (phần lớn tham số attention/MLP) xuống 4-bit; embedding của Qwen2.5-0.5B-Instruct một mình đã chiếm 136.1M trên tổng 494M tham số (~27.6% toàn bộ model), và ở fp16 riêng embedding này đã nặng khoảng 272MB — tức khoảng 60% dung lượng của TOÀN BỘ model 4-bit (451MB). Vì phần giữ nguyên độ chính xác cao chiếm tỷ trọng lớn như vậy (không phải một chi tiết nhỏ có thể bỏ qua), tỷ lệ nén thực tế đo được luôn thấp hơn đáng kể so với tỷ lệ bit lý thuyết — đúng cơ chế sẽ đo lại và giải thích kỹ hơn ở bài 06. Cộng phần này với kết quả bài 01: base model 4-bit (0.451 GB) + LoRA adapter fp32/fp16 (chỉ vài MB, theo đúng tỷ lệ 0.1094% đã đo) là chính xác định nghĩa của QLoRA — full fine-tune-level chất lượng train, ở mức bộ nhớ đủ nhỏ để chạy trên 1 GPU tiêu dùng.

Tổng kết & bài tiếp theo

LoRALinear tự viết khớp tuyệt đối với peft.LoraConfig (sai số 0.000e+00) trên đúng một layer thật của Qwen2.5-0.5B-Instruct, và giữ đúng tính chất B=0 không phá model gốc lúc init. QLoRA nén base model xuống 4-bit, đo thật giảm 77.2% dung lượng, giải quyết đúng phần model weights mà LoRA thường không đụng tới.
