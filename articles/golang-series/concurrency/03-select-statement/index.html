03. Select statement

Oct 26, 2026 · 5 min read

Series · Go Concurrency

Bài 02 học cách 1 channel hoạt động. Bài này đi vào select — cách làm việc với nhiều channel cùng lúc, và cách thoát khỏi tình huống có thể deadlock bằng timeout thay vì chờ vô thời hạn.

select cơ bản: chờ nhiều channel, xử lý cái nào sẵn sàng trước

fast := make(chan string)
slow := make(chan string)

go func() {
    time.Sleep(100 * time.Millisecond)
    fast <- "fast xong"
}()
go func() {
    time.Sleep(400 * time.Millisecond)
    slow <- "slow xong"
}()

for i := 0; i < 2; i++ {
    select {
    case msg := <-fast:
        fmt.Println(time.Now().Format("15:04:05.000"), "nhận từ fast:", msg)
    case msg := <-slow:
        fmt.Println(time.Now().Format("15:04:05.000"), "nhận từ slow:", msg)
    }
}
06:18:04.484 nhận từ fast: fast xong
06:18:04.784 nhận từ slow: slow xong

Chênh lệch đúng 300ms giữa 2 dòng — khớp chính xác với 400ms - 100ms. select block cho tới khi ít nhất 1 channel sẵn sàng, luôn xử lý đúng channel có dữ liệu trước — không cần code polling hay kiểm tra tuần tự từng channel.

Timeout pattern với time.After

Pattern kinh điển nhất khi dùng select: không chờ mãi mãi 1 channel có thể không bao giờ có dữ liệu.

func slowCall() <-chan string {
    ch := make(chan string)
    go func() {
        time.Sleep(3 * time.Second) // giả lập lời gọi rất chậm
        ch <- "kết quả"
    }()
    return ch
}

start := time.Now()
select {
case res := <-slowCall():
    fmt.Println("nhận được:", res)
case <-time.After(1 * time.Second):
    fmt.Println("TIMEOUT sau", time.Since(start).Round(time.Millisecond))
}
TIMEOUT sau 1.001s

slowCall() mất 3 giây, nhưng chương trình chỉ chờ đúng ~1 giây rồi bỏ cuộc — time.After(1*time.Second) trả về 1 channel tự động nhận được giá trị sau đúng khoảng thời gian đó, select chọn nhánh nào sẵn sàng trước. Goroutine chạy slowCall() vẫn tiếp tục chạy ngầm cho tới khi xong (rồi tự kết thúc vì không ai nhận ch nữa) — select chỉ đơn giản ngừng chờ, không hề huỷ được goroutine đang chạy dở (muốn huỷ thật sự cần context.Context, chủ đề của mini-series sau).

default case: non-blocking channel operation

ch := make(chan int)
select {
case v := <-ch:
    fmt.Println("có dữ liệu:", v)
default:
    fmt.Println("chưa có dữ liệu, không chờ")
}
chưa có dữ liệu, không chờ

Không có default, select này sẽ block vô thời hạn chờ ch. Có default, Go thử nhận ngay lập tức, không có thì chạy default — không chờ, không block. Thử lại với channel đã có sẵn dữ liệu:

ch2 := make(chan int, 1)
ch2 <- 42
select {
case v := <-ch2:
    fmt.Println("có dữ liệu:", v)
default:
    fmt.Println("chưa có dữ liệu, không chờ")
}
có dữ liệu: 42

Dùng khi nào: kiểm tra “channel có dữ liệu ngay lúc này không” mà không muốn luồng chính dừng lại chờ — ví dụ vòng lặp xử lý việc khác, tiện thể “liếc qua” channel thông báo mỗi vòng lặp.

Bẫy: for-select với time.After tạo trong vòng lặp

Pattern hay bị viết sai: đặt time.After bên trong vòng lặp select chạy lặp lại nhiều lần — mỗi lần vào select lại tạo 1 timer hoàn toàn mới. Trên Go bản cũ (trước 1.23), timer chưa fire mà không còn ai giữ tham chiếu không được garbage collector dọn ngay — vòng lặp chạy nhanh hơn thời lượng timer sẽ tích luỹ ngày càng nhiều timer treo lơ lửng, tốn bộ nhớ thật. Từ Go 1.23, runtime đã cải thiện: timer không còn tham chiếu có thể được GC dọn ngay cả khi chưa fire, giảm hẳn mức độ nghiêm trọng của vấn đề này trên Go hiện đại (bài viết dùng Go 1.24). Dù vậy, tạo mới 1 timer mỗi vòng lặp vẫn là cấp phát thừa không cần thiết — thói quen đúng là tạo timer/ticker 1 lần, tái sử dụng qua Reset() nếu cần lặp lại.

Cách đúng: time.NewTicker cho công việc lặp lại định kỳ

ticker := time.NewTicker(200 * time.Millisecond) // tạo đúng 1 lần
defer ticker.Stop()

done := make(chan bool)
go func() {
    time.Sleep(900 * time.Millisecond)
    done <- true
}()

count := 0
for {
    select {
    case <-done:
        fmt.Println("Hoàn tất, đã tick", count, "lần")
        return
    case t := <-ticker.C:
        count++
        fmt.Println("tick", count, "lúc", t.Format("15:04:05.000"))
    }
}
tick 1 lúc 06:18:05.985
tick 2 lúc 06:18:06.185
tick 3 lúc 06:18:06.385
tick 4 lúc 06:18:06.585
Hoàn tất, đã tick 4 lần

Đúng 4 tick trong 900ms với chu kỳ 200ms (0.985 → 6.585, chia đều 200ms 1 lần) — ticker.C là cùng 1 channel trong suốt vòng đời ticker, không tạo mới mỗi vòng lặp. defer ticker.Stop() giải phóng tài nguyên đúng lúc hàm kết thúc — luôn nhớ Stop() một Ticker khi không cần nữa (khác time.After, Ticker chạy vô thời hạn cho tới khi bị dừng tường minh).

Tự chạy lại demo

cd 03-select-statement
go run .
go vet ./...

main.go gộp cả 4 demo (select cơ bản, timeout, default case, ticker), chạy tuần tự cho đúng output như các đoạn ở trên (tổng thời gian chạy khoảng 2 giây do các time.Sleep/timeout trong demo).

Tổng kết & bài tiếp theo

select là công cụ multiplexing trung tâm của Go concurrency: chọn đúng channel sẵn sàng trước, kết hợp time.After để không bao giờ chờ vô thời hạn, và default cho thao tác không muốn block. Với công việc lặp lại định kỳ, luôn ưu tiên time.NewTicker/time.NewTimer tái sử dụng thay vì tạo mới time.After mỗi vòng lặp.
