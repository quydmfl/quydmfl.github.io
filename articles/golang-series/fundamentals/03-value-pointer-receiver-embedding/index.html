03. Value vs Pointer receiver & struct embedding

Go truyền mọi thứ theo giá trị (pass by value) — kể cả struct. Bài này đi vào hệ quả trực tiếp: khi nào 1 struct bị copy mà lập trình viên không nhận ra, và vì sao chọn sai giữa value/pointer receiver là nguồn bug âm thầm phổ biến.

Value receiver: method nhận bản copy

type CounterWrong struct{ n int }

func (c CounterWrong) Inc() { c.n++ } // value receiver: sửa bản copy
wrong := CounterWrong{}
for i := 0; i < 5; i++ {
    wrong.Inc()
}
fmt.Println("wrong.n =", wrong.n)
wrong.n = 0

0, không phải 5 — mỗi lần gọi wrong.Inc(), Go tạo 1 bản copy của CounterWrong, c.n++ chỉ tăng trên bản copy đó, rồi bản copy bị vứt bỏ ngay khi hàm kết thúc. Struct gốc wrong chưa từng bị đổi.

Pointer receiver: method thao tác trực tiếp

type CounterRight struct{ n int }

func (c *CounterRight) Inc() { c.n++ } // pointer receiver: sửa struct gốc
right := CounterRight{}
for i := 0; i < 5; i++ {
    right.Inc()
}
fmt.Println("right.n =", right.n)
right.n = 5

5, đúng như kỳ vọng — c giờ là địa chỉ của right, c.n++ sửa thẳng lên struct gốc. Quy tắc thực dụng: struct có bất kỳ method nào cần sửa state thì toàn bộ method của struct đó nên dùng pointer receiver — trộn lẫn value/pointer receiver trên cùng 1 struct là nguồn nhầm lẫn không cần thiết.

Method set: khác biệt giữa T và *T

Interface chỉ được thoả mãn bởi *T nếu method dùng pointer receiver — T (value) không tự động có method đó trong method set của nó. Thử truyền value thay vì pointer vào chỗ cần interface:

type Incrementer interface {
    Inc()
}

func useIncrementer(inc Incrementer) {
    inc.Inc()
}

c := CounterRight{}
useIncrementer(c) // truyền value, không phải pointer

Lỗi biên dịch thật:

./methodset_fail.go:17:17: cannot use c (variable of struct type CounterRight) as
Incrementer value in argument to useIncrementer: CounterRight does not implement
Incrementer (method Inc has pointer receiver)

Go từ chối biên dịch — rất tốt, đây là bug bị chặn ngay tại compile-time thay vì lọt tới runtime. Sửa bằng cách truyền &c:

useIncrementer(&c) // đúng: *CounterRight thoả mãn Incrementer
Sau khi truyền &c: 1

Struct embedding — “kế thừa” kiểu Go

type Engine struct{ Power int }

func (e Engine) Start() string { return fmt.Sprintf("engine started, power=%d", e.Power) }

type Car struct {
    Engine // embedding -- không có tên field, chỉ có tên type
    Brand  string
}

car := Car{Engine: Engine{Power: 150}, Brand: "Toyota"}
fmt.Println(car.Start())      // promoted method
fmt.Println(car.Power)        // promoted field
fmt.Println(car.Engine.Power) // vẫn truy cập tường minh được qua tên type
engine started, power=150
150
150

car.Start() và car.Power gọi được thẳng dù Car không tự định nghĩa Start()/Power — Go tự “promote” field/method của type được embed lên struct ngoài. Điểm quan trọng cần nhớ: đây không phải kế thừa thật — không có polymorphism qua embedding (không thể gán 1 Car vào biến kiểu Engine và mong đợi override hoạt động như OOP truyền thống), chỉ đơn thuần là cú pháp rút gọn cho việc gọi field/method của struct lồng bên trong.

Bẫy: 2 struct embedded cùng tên method

type Engine struct{}
func (e Engine) Start() string { return "engine started" }

type Alarm struct{}
func (a Alarm) Start() string { return "alarm started" }

type Car struct {
    Engine
    Alarm
}

car := Car{}
car.Start() // ?

Lỗi biên dịch thật:

./ambiguous.go:18:14: ambiguous selector car.Start

Go từ chối tự chọn method nào trong 2 method trùng tên — đúng chủ đích, tránh việc chọn nhầm 1 cách âm thầm. Sửa bằng cách gọi tường minh qua tên type embedded:

fmt.Println(car.Engine.Start())
fmt.Println(car.Alarm.Start())
engine started
alarm started

Tự chạy lại demo

cd 03-value-pointer-receiver-embedding
go run .
go vet ./...

main.go gộp 4 demo chạy được (value/pointer receiver, method set đúng cách, embedding, fix ambiguous selector). Riêng 2 lỗi biên dịch thật ở trên (method set sai, ambiguous selector) không nằm trong main.go — vì bản chất chúng khiến cả file không biên dịch được — có thể tự tái hiện bằng cách tách đoạn code tương ứng ra 1 file .go riêng rồi chạy go build.

Tổng kết & bài tiếp theo

Ba điều cần nhớ: value receiver luôn thao tác trên bản copy (âm thầm, không cảnh báo runtime); method set của T và *T khác nhau thật sự, được compiler enforce nghiêm ngặt; và embedding chỉ là promotion cú pháp, không phải kế thừa — 2 lỗi biên dịch thật ở trên (method has pointer receiver, ambiguous selector) chính là compiler đang bảo vệ đúng những ranh giới này.
