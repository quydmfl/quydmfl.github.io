02. Build & binary optimization

Nov 14, 2026 · 5 min read

Series · Go Performance & Production

  1. 01. PGO (Profile-Guided Optimization)
  2. 02. Build & binary optimization
  3. 03. Graceful shutdown
  4. 04. GOMEMLIMIT & container awareness

Bài 01 tối ưu tốc độ chạy. Bài này tối ưu chính quá trình build và bản thân binary output — những flag nên có mặt trong mọi pipeline CI/CD build Go production, đo trên 1 server nhỏ dùng net/http + encoding/json (đủ phức tạp để có kích thước binary thực tế, không phải “hello world” trơn).

-ldflags="-s -w": giảm kích thước binary

-s loại bỏ symbol table, -w loại bỏ debug info (DWARF) — cả 2 chỉ ảnh hưởng metadata cho việc debug, không đổi hành vi chương trình:

go build -o app .                          # mặc định
go build -ldflags="-s -w" -o app_stripped . # strip symbol + debug info
app:          5211986 bytes
app_stripped: 3598882 bytes

Giảm 30.9% kích thước chỉ với 1 flag — đổi lại mất khả năng debug trực tiếp bằng delve trên binary release (không còn symbol table để map địa chỉ máy về tên hàm/dòng code), và stack trace panic sẽ không còn tên hàm dễ đọc. Với binary release production (không phải bản debug nội bộ), đây gần như luôn là đánh đổi đáng làm.

CGO_ENABLED=0: static binary thật — kiểm chứng bằng file

Trên Linux, CGO_ENABLED=0 tạo binary static hoàn toàn, không phụ thuộc libc hệ thống nào — quan trọng nhất khi chạy trên image tối giản như scratch (bài 06):

GOOS=linux GOARCH=amd64 CGO_ENABLED=0 go build -o app_linux .
file app_linux
app_linux: ELF 64-bit LSB executable, x86-64, version 1 (SYSV), statically linked, BuildID[sha1]=..., with debug_info, not stripped

file xác nhận thẳng: statically linked — không cần bất kỳ thư viện động nào tại runtime. Thử ngược lại, cross-compile sang Linux với CGO_ENABLED=1 từ máy macOS (không có cross C compiler cho Linux):

# runtime/cgo
linux_syscall.c:67:13: error: call to undeclared function 'setresgid'
...
cannot open `app_linux_cgo1' (No such file or directory)

Build thất bại hoàn toàn — đây là lý do thực dụng thứ 2 để dùng CGO_ENABLED=0: không chỉ tạo binary static, mà còn cho phép cross-compile sang OS/arch khác mà không cần cài cross C toolchain — chỉ cần Go toolchain sẵn có. Đây chính xác là setup phổ biến khi build Go trên macOS/Windows để deploy container Linux (bài 06).

Lưu ý trên macOS: kể cả với CGO_ENABLED=0, binary build cho chính macOS vẫn liên kết 1 số thư viện hệ thống cơ bản (libSystem, CoreFoundation) — đây là đặc thù của Darwin (Go runtime cần vài syscall qua các framework này), không phải do cgo. Static hoàn toàn theo đúng nghĩa “zero dependency” chỉ thể hiện rõ ràng trên Linux như demo trên.

Build cache: vì sao lần build thứ 2 luôn nhanh hơn

Go cache kết quả compile từng package tại $GOCACHE — build lại không đổi gì gần như tức thời:

go clean -cache   # xoá sạch cache để đo build "lạnh"
time go build -o app .
# real: 3.697s

time go build -o app .   # build lại ngay, cache đã có
# real: 0.279s

Nhanh hơn ~13 lần (3.697s / 0.279s) chỉ nhờ cache — với dự án lớn hơn nhiều package, chênh lệch tuyệt đối còn lớn hơn. Đây là lý do CI pipeline nên cache thư mục $GOCACHE giữa các lần chạy (hầu hết CI provider đều hỗ trợ cache theo key), không rebuild từ đầu mỗi lần.

-trimpath: build reproducible

Mặc định, binary chứa đường dẫn tuyệt đối trên máy build:

go build -o app_notrim .
strings app_notrim | grep "02-build-binary-optimization"
/Users/duongquy/workspace/.../02-build-binary-optimization/main.go

Lộ nguyên đường dẫn máy build — không chỉ là vấn đề thẩm mỹ, mà khiến build trên 2 máy khác nhau (hoặc 2 lần chạy CI với workspace path khác nhau) cho ra binary khác byte dù code giống hệt, phá vỡ tính “reproducible build” (build lại từ cùng source phải cho ra cùng 1 checksum). Thêm -trimpath:

go build -trimpath -o app_trim .
strings app_trim | grep "02-build-binary-optimization"

Không có kết quả nào — đường dẫn đã bị loại bỏ hoàn toàn khỏi binary.

Tổng hợp: build production chuẩn

CGO_ENABLED=0 go build -trimpath -ldflags="-s -w" -o app .
Mặc định:      5211986 bytes
Tổng hợp đủ:   3582354 bytes

Giảm 31.3% tổng thể — gần như toàn bộ mức giảm tới từ -s -w (-trimpath/CGO_ENABLED=0 đóng góp phần nhỏ hơn về kích thước, nhưng quan trọng cho tính static và reproducible chứ không chỉ dung lượng).

Tự chạy lại demo

cd 02-build-binary-optimization
go run .
go vet ./...

go build -ldflags="-s -w" -o app_stripped .
GOOS=linux GOARCH=amd64 CGO_ENABLED=0 go build -o app_linux . && file app_linux
go build -trimpath -o app_trim . && strings app_trim | grep "02-build-binary-optimization"
CGO_ENABLED=0 go build -trimpath -ldflags="-s -w" -o app_full .

Tổng kết & bài tiếp theo

-ldflags="-s -w" giảm ~31% kích thước binary gần như miễn phí cho build production. CGO_ENABLED=0 tạo static binary thật trên Linux (kiểm chứng bằng file) và cho phép cross-compile không cần cross toolchain — nền tảng cho Docker image tối giản ở bài 06. Build cache giúp lần build thứ 2 trở đi nhanh hơn ~13 lần. -trimpath loại bỏ đường dẫn máy build, cần thiết cho reproducible build.
