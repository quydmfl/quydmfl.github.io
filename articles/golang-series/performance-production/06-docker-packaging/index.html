Bài cuối cùng khép lại toàn bộ series Go: đóng gói ứng dụng Go thành Docker image, tận dụng static binary đã học ở bài 02 để có image tối giản nhất có thể. Toàn bộ số liệu trong bài chạy trên Docker thật.

Multi-stage build: tách rời build-time và runtime

FROM golang:1.24 AS builder
WORKDIR /src
COPY go.mod .
COPY main.go .
RUN CGO_ENABLED=0 GOOS=linux go build -trimpath -ldflags="-s -w" -o /app .

FROM scratch
COPY --from=builder /app /app
ENTRYPOINT ["/app"]

Stage 1 (builder) có đầy đủ toolchain Go để build — image này không được ship, chỉ dùng tạm trong quá trình build (và có lợi ích phụ: không cần cài Go trên máy dev, chỉ cần Docker). Stage 2 chỉ COPY --from=builder đúng file binary đã build sang image scratch — loại bỏ hoàn toàn toolchain, source code khỏi image cuối cùng:

docker build -t myapp .
docker run -d -p 8080:8080 myapp
curl http://localhost:8080/
{"message":"OK","time":"2026-09-12T05:21:30Z"}

Server chạy đúng trong image scratch — xác nhận CGO_ENABLED=0 (bài 02) tạo ra binary static hoàn toàn, không cần bất kỳ thư viện hệ thống nào có sẵn trong image.

So sánh kích thước image thật

Build cùng 1 source code, cùng binary (từ cùng builder stage), chỉ đổi base image ở stage cuối — 4 biến thể: ubuntu:22.04, alpine:3.19, gcr.io/distroless/static-debian12, scratch:

docker images
REPOSITORY          DISK USAGE   CONTENT SIZE
pp06-ubuntu          115MB        29.9MB
pp06-alpine          19.4MB        5.59MB
pp06-distroless      13.8MB        2.95MB
pp06-multistage        7.61MB       2.23MB

Chênh lệch ~15 lần giữa ubuntu (115MB) và scratch (7.61MB) cho cùng 1 ứng dụng — gần như toàn bộ 115MB của base image ubuntu là hệ điều hành đầy đủ (shell, package manager, thư viện hệ thống) mà ứng dụng Go không cần dùng tới bất kỳ phần nào, vì binary đã static hoàn toàn. CONTENT SIZE (kích thước nén, ảnh hưởng thời gian pull qua network) cũng chênh tương tự: 29.9MB vs 2.23MB.

scratch: nhỏ nhất, nhưng không debug được bên trong

docker exec <container-scratch> sh -c "echo hello"
OCI runtime exec failed: exec failed: unable to start container process: exec: "sh": executable file not found in $PATH

Không có shell — docker exec vào container scratch thất bại ngay, vì bên trong hoàn toàn không có gì ngoài binary vừa copy vào. Mọi debug phải qua log/metrics/pprof đã học ở bài 05, không có “vào trong xem thử” như thói quen quen thuộc với container base image đầy đủ. Đối chứng với alpine (có shell ash):

docker exec <container-alpine> sh -c "echo hello, có shell"
hello, có shell

distroless: điểm cân bằng phổ biến

docker exec <container-distroless> sh -c "echo hello"
OCI runtime exec failed: exec failed: unable to start container process: exec: "sh": executable file not found in $PATH

distroless (gcr.io/distroless/static-debian12) cũng không có shell — cùng mức an toàn với scratch về bề mặt tấn công, nhưng có sẵn CA certificates (cần cho gọi HTTPS ra ngoài) và timezone data (cần cho time.LoadLocation với tên timezone) — 2 thứ hay bị quên khi dùng scratch thuần, gây lỗi khó hiểu lúc runtime (ví dụ: gọi API HTTPS ra ngoài thất bại vì thiếu root CA, hoặc time.LoadLocation("Asia/Ho_Chi_Minh") lỗi vì thiếu dữ liệu timezone). Kích thước 13.8MB chỉ nhích hơn scratch (7.61MB) một chút để đổi lấy 2 thứ đó — thường là điểm cân bằng hợp lý cho production thật, trừ khi ứng dụng chắc chắn không cần cả 2 (ví dụ chỉ giao tiếp nội bộ HTTP thuần, không xử lý timezone).

Tự chạy lại demo

cd 06-docker-packaging
go run .              # chạy thử server trực tiếp, không cần Docker
go vet ./...

docker build -t myapp .
docker run -d -p 8080:8080 myapp
curl http://localhost:8080/
docker exec <container> sh   # sẽ lỗi -- không có shell trong scratch

main.go + go.mod + Dockerfile (multi-stage, đích scratch) là toàn bộ những gì cần để build và chạy — không cần cài Go trên máy để build image (toolchain nằm trong stage builder), chỉ cần Docker.

Tổng kết mini-series & toàn bộ series Go

Multi-stage build tách build-time (toolchain đầy đủ) khỏi runtime (chỉ binary) — kết hợp với static binary từ bài 02, image cuối cùng có thể nhỏ hơn base image thông thường tới ~15 lần. scratch nhỏ nhất nhưng không debug được bên trong; distroless nhích hơn 1 chút để có CA certs + timezone data, thường là lựa chọn thực dụng nhất cho service HTTP thật.
