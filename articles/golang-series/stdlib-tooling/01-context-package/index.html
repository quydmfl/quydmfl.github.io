01. context package

Nov 6, 2026 · 6 min read

Mở đầu mini-series Standard Library & Tooling: context là gói xuất hiện ở gần như mọi hàm I/O trong Go hiện đại (HTTP handler, database query, RPC call), nhưng cơ chế cancellation/deadline bên dưới nó thường bị dùng sai mà không hay biết.

context.Background/TODO: gốc của mọi cây context

context.Background() là gốc thật sự — dùng ở main(), khởi tạo request, test. context.TODO() mang cùng hành vi (không bao giờ Done(), không có value) nhưng là tín hiệu cho người đọc code: “chỗ này cần 1 context thật, nhưng chưa rõ lấy từ đâu — cần refactor sau”. Về mặt hành vi runtime, 2 hàm này giống hệt nhau; khác biệt duy nhất là ý nghĩa với người đọc.

WithTimeout/WithCancel: ctx.Done() đóng khi nào, ctx.Err() báo gì

ctx, cancel := context.WithTimeout(context.Background(), 200*time.Millisecond)
defer cancel()
<-ctx.Done()
fmt.Println(ctx.Err())

ctx2, cancel2 := context.WithCancel(context.Background())
go func() {
    time.Sleep(100 * time.Millisecond)
    cancel2()
}()
<-ctx2.Done()
fmt.Println(ctx2.Err())
WithTimeout: ctx.Done() đóng sau 201ms | ctx.Err(): context deadline exceeded
WithCancel : ctx.Done() đóng sau 101ms | ctx.Err(): context canceled

ctx.Done() trả về 1 channel — đóng khi context bị huỷ, dù chủ động (cancel()) hay tự động (hết timeout/deadline). ctx.Err() phân biệt rõ 2 nguyên nhân: context.DeadlineExceeded (hết hạn tự động) và context.Canceled (ai đó gọi cancel() chủ động) — code xử lý lỗi phía sau có thể phản ứng khác nhau tuỳ trường hợp (ví dụ: hết hạn thì retry với timeout dài hơn, bị huỷ chủ động thì dừng hẳn).

Context leak: quên gọi cancel() — và go vet bắt được ngay

WithCancel/WithTimeout trả về 1 hàm cancel — bỏ qua nó (ctx, _ := context.WithCancel(...)) là lỗi rất dễ mắc, và hậu quả là goroutine leak thật:

func leakyWorker(ctx context.Context) {
    <-ctx.Done() // chờ mãi vì không ai gọi cancel()
}

for i := 0; i < 1000; i++ {
    ctx, _ := context.WithCancel(context.Background()) // bỏ qua cancel func -- LEAK
    go leakyWorker(ctx)
}

Trước khi chạy thử, go vet đã phát hiện ngay:

./leak.go:21:8: the cancel function returned by context.WithCancel should be called, not discarded, to avoid a context leak

Đây là 1 check tên lostcancel được tích hợp sẵn trong go vet — bắt chính xác pattern này ở tầng phân tích tĩnh, trước cả khi chương trình chạy. Bỏ qua cảnh báo và chạy thử để thấy hậu quả thật:

NumGoroutine trước: 1
NumGoroutine sau 1000 leaky worker: 1001 (tăng đúng 1000, không bao giờ giảm)

1000 goroutine kẹt vĩnh viễn ở <-ctx.Done() — không context nào trong số đó bao giờ đóng vì không ai gọi cancel(), và cũng không có WithTimeout để tự động hết hạn. Trên 1 service chạy dài ngày, mỗi request tạo 1 context kiểu này là 1 goroutine leak tích luỹ dần cho tới khi hết bộ nhớ.

So sánh với cách dùng đúng — gọi cancel() ngay khi context không còn cần:

ctx, cancel := context.WithCancel(context.Background())
go worker(ctx)
cancel()
NumGoroutine trước: 1
NumGoroutine sau 1000 worker CÓ cancel(): 1 (không tích luỹ, tự thoát hết)

Quay lại đúng baseline 1 — toàn bộ 1000 goroutine đã thoát sạch. Quy tắc thực dụng: luôn defer cancel() ngay sau khi tạo context từ WithCancel/WithTimeout/WithDeadline, kể cả khi chắc chắn context sẽ tự hết hạn — cancel() còn giải phóng tài nguyên nội bộ khác (gỡ liên kết khỏi context cha, dừng timer) mà tự hết hạn không làm hết.

WithValue: truyền dữ liệu request-scoped qua nhiều tầng hàm

type ctxKey string
const requestIDKey ctxKey = "requestID"

func handleRequest(ctx context.Context) { processStep1(ctx) }
func processStep1(ctx context.Context) { processStep2(ctx) }
func processStep2(ctx context.Context) {
    reqID, ok := ctx.Value(requestIDKey).(string)
    fmt.Println(reqID, ok)
}

ctx := context.WithValue(context.Background(), requestIDKey, "req-12345")
handleRequest(ctx)
Ở tầng sâu nhất (processStep2), đọc được requestID: req-12345 | ok: true
Đọc key không tồn tại trên context khác: giá trị = "" | ok: false

requestID truyền xuyên qua handleRequest → processStep1 → processStep2 mà không sửa signature của 2 tầng giữa — đây chính là lý do WithValue tồn tại: mang dữ liệu gắn với vòng đời 1 request (request ID, trace ID, thông tin auth đã xác thực) đi xuyên qua các tầng gọi hàm không liên quan trực tiếp tới dữ liệu đó. Dùng type ctxKey string riêng (không dùng string trần) tránh đụng độ key giữa các package khác nhau vô tình dùng cùng chuỗi.

Không nên dùng WithValue thay cho tham số hàm thông thường — nếu 1 hàm thực sự cần 1 giá trị để hoạt động đúng, hãy truyền nó tường minh qua tham số; context.Value không có kiểm tra kiểu tại compile-time (phải type-assert, có thể ok: false bất ngờ) và làm code khó theo dõi dữ liệu đi từ đâu.

Context tree: huỷ gốc lan truyền xuống toàn bộ con/cháu

root, cancelRoot := context.WithCancel(context.Background())
child1, _ := context.WithCancel(root)
child2, _ := context.WithCancel(root)
grandchild, _ := context.WithCancel(child1)

// mỗi context có 1 goroutine chờ ctx.Done()

cancelRoot()
Huỷ context GỐC (root)...
Toàn bộ con + cháu thoát sau: 25.167µs
Thứ tự thoát: [child2 child1 grandchild (con của child1)]

Huỷ đúng 1 context gốc khiến cả child1, child2, và grandchild (cháu, con của child1) cùng thoát trong ~25 micro giây — không cần huỷ thủ công từng context con. Đây là lý do context luôn nên được truyền xuyên suốt 1 luồng xử lý (thay vì mỗi tầng tự tạo context.Background() riêng): huỷ đúng 1 điểm ở tầng cao nhất (ví dụ: client ngắt kết nối HTTP) tự động dọn dẹp toàn bộ cây công việc con bên dưới, dù cây đó sâu bao nhiêu tầng.

Tự chạy lại demo

cd 01-context-package
go run .
go vet ./...

main.go gộp 4 demo an toàn (WithTimeout/WithCancel, dùng cancel() đúng cách, WithValue, context tree). Demo leak (ctx, _ := context.WithCancel(...)) không nằm trong main.go — go vet ./... sẽ chặn ngay với lỗi lostcancel nếu để trong module chính; tách thành đoạn code riêng để tự tái hiện cả cảnh báo vet lẫn hành vi leak thật khi cố tình bỏ qua cảnh báo đó.

Tổng kết & bài tiếp theo

context cung cấp 2 cơ chế độc lập: cancellation/deadline (qua Done()/Err()) và truyền dữ liệu request-scoped (qua Value()). Context hình thành cây — huỷ gốc lan truyền xuống toàn bộ con/cháu gần như tức thời. Quên gọi cancel() là goroutine leak thật, nhưng may mắn là 1 trong số ít lỗi runtime phổ biến được chính go vet phát hiện tĩnh trước khi chạy — luôn chạy go vet như 1 bước bắt buộc, không chỉ để bắt lỗi cú pháp.
