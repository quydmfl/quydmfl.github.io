Bài 02 dùng io.Reader/io.Writer cho request/response body mà không nói rõ. Bài này mổ xẻ 2 interface tối giản nhưng nền tảng nhất của I/O trong Go, và lý do bufio gần như luôn cần thiết khi đọc/ghi dữ liệu lớn.

io.Reader/io.Writer: interface 1 method, compose vô hạn

type Reader interface {
    Read(p []byte) (n int, err error)
}
type Writer interface {
    Write(p []byte) (n int, err error)
}

Chỉ 2 method, nhưng mọi nguồn/đích dữ liệu trong Go đều implement chúng: file (*os.File), network connection (net.Conn), buffer trong bộ nhớ (*bytes.Buffer), chuỗi (*strings.Reader), compression stream (*gzip.Writer)… Nhờ interface tối giản này, code viết cho io.Reader chạy được với bất kỳ nguồn dữ liệu nào implement nó — hàm nhận io.Reader không cần biết (và không nên quan tâm) đó là file hay network.

io.Copy: vòng lặp Read/Write với buffer tạm

var buf bytes.Buffer
src := strings.NewReader(strings.Repeat("x", 100000))
n, err := io.Copy(&buf, src)
Đã copy 100000 byte, lỗi: <nil> | buf.Len(): 100000

Đọc thẳng source code io.Copy (io/io.go): vòng lặp gọi Read vào 1 buffer cố định 32KB (size := 32 * 1024), rồi Write buffer đó ra đích, lặp lại tới khi gặp io.EOF. Không cần biết trước tổng kích thước dữ liệu — hoạt động y hệt với 100.000 byte trong bộ nhớ như ở demo trên, hay 1 stream vô hạn từ network.

bufio giảm số lần syscall thật — chênh lệch hơn 200 lần

Đọc trực tiếp không qua buffer, mỗi lời gọi Read nhỏ tương ứng 1 syscall — cực kỳ tốn kém khi gọi lặp lại với dữ liệu nhỏ. Đo thật: đọc 500.000 byte đầu của 1 file, từng byte 1 lần gọi, so với qua bufio.Reader:

// Không buffer -- mỗi byte 1 lần gọi f.Read(), tương ứng 1 syscall
f, _ := os.Open(path)
buf := make([]byte, 1)
for count < readN {
    f.Read(buf)
    count++
}

// Có bufio.Reader -- syscall thật chỉ xảy ra khi buffer nội bộ cạn
r := bufio.NewReader(f)
for count < readN {
    r.ReadByte()
    count++
}
BenchmarkReadByteNoBuffer-10    5    210681333 ns/op     289 B/op    4 allocs/op
BenchmarkReadByteBuffered-10    5      1025442 ns/op    4385 B/op    5 allocs/op

Chênh lệch ~205 lần (210681333 / 1025442) cho cùng 500.000 byte đọc ra. Nguyên nhân: bufio.NewReader mặc định dùng buffer nội bộ 4096 byte (defaultBufSize trong bufio/bufio.go) — mỗi lần buffer cạn mới thực hiện 1 syscall Read thật lấy đầy 4096 byte, giảm số syscall từ 500.000 lần (1/byte) xuống còn khoảng 122 lần (500.000/4096) — ít hơn ~4096 lần về số syscall, phản ánh gần đúng vào mức chênh lệch thời gian đo được. Bài học thực dụng: luôn bọc bufio.NewReader/bufio.NewWriter quanh file/network I/O khi đọc/ghi theo từng phần nhỏ (từng dòng, từng byte, từng token) — không bao giờ nên bỏ qua, kể cả “chỉ để chắc chắn”.

io.CopyBuffer: kiểm soát kích thước buffer trung gian

io.Copy dùng buffer mặc định 32KB không thể thay đổi. io.CopyBuffer cho phép chỉ định buffer riêng:

buf := make([]byte, 64*1024) // buffer lớn hơn mặc định, tái sử dụng qua nhiều lần copy
io.CopyBuffer(dst, src, buf)

Hữu ích khi copy nhiều luồng đồng thời và muốn tái sử dụng cùng 1 buffer (qua sync.Pool, liên hệ Runtime Internals bài 04) thay vì để io.Copy tự cấp phát buffer 32KB mới cho mỗi lần gọi — giảm áp lực GC khi copy diễn ra với tần suất cao.

Compose nhiều Reader: MultiReader, TeeReader

io.MultiReader nối nhiều Reader thành 1 luồng liên tục — đọc hết Reader này mới sang Reader kế tiếp:

combined := io.MultiReader(
    strings.NewReader("Phần 1. "),
    strings.NewReader("Phần 2. "),
    strings.NewReader("Phần 3."),
)
data, _ := io.ReadAll(combined)
Kết quả: Phần 1. Phần 2. Phần 3.

io.TeeReader đọc từ 1 Reader, đồng thời ghi những gì vừa đọc được sang 1 Writer khác — dùng tốt cho vừa đọc dữ liệu vừa tính checksum/log mà không cần đọc 2 lần:

hasher := sha256.New()
tee := io.TeeReader(strings.NewReader("dữ liệu cần vừa đọc vừa hash"), hasher)
content, _ := io.ReadAll(tee)
Đọc được: dữ liệu cần vừa đọc vừa hash
SHA256 tính được trong lúc đọc: 3969b81b671289c1d6b85fc3ceaca771cd768e96827bd5c1f5ebc757eb84d8a7

Hash tính được khớp chính xác với shasum -a 256 chạy độc lập trên cùng chuỗi — xác nhận TeeReader không làm sai lệch dữ liệu trong lúc “chụp” 1 bản sao sang hasher, dù việc đọc và hash xảy ra trong cùng 1 lượt duyệt qua dữ liệu.

Tự chạy lại demo

cd 03-io-bufio
go run .
go vet ./...
go test -bench . -benchmem -run '^$'

main.go gộp 3 demo (io.Copy, io.MultiReader, io.TeeReader). readbench_test.go tự tạo 1 file tạm đủ lớn trong thư mục temp của hệ điều hành (không commit file dữ liệu lớn vào repo) cho 2 benchmark buffered/unbuffered ở trên.

Tổng kết & bài tiếp theo

io.Reader/io.Writer là 2 interface 1 method nhưng compose được thành mọi pipeline I/O phức tạp. io.Copy dùng buffer 32KB cố định, không cần biết trước kích thước dữ liệu. bufio giảm số syscall bằng cách gom nhiều thao tác nhỏ thành ít lần đọc/ghi lớn hơn — chênh lệch thật đo được hơn 200 lần cho thao tác đọc từng byte, khiến nó gần như luôn là lựa chọn bắt buộc chứ không phải tối ưu tuỳ chọn.
