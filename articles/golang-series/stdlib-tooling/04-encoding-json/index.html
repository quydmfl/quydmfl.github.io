Bài 03 học io.Reader/io.Writer. Bài này xem encoding/json dùng chúng thế nào qua Decoder/Encoder, và mổ xẻ chi phí reflection — thứ khiến encoding/json chậm hơn hẳn code viết tay biết trước chính xác cấu trúc dữ liệu.

Reflection đứng sau Marshal/Unmarshal: đo chi phí thật

json.Marshal dùng reflect để duyệt field của struct tại runtime, đọc struct tag, quyết định cách encode từng field — linh hoạt (hoạt động với bất kỳ struct nào) nhưng có chi phí thật. So sánh với 1 hàm viết tay biết trước chính xác 2 field X, Y:

type Point struct {
    X int `json:"x"`
    Y int `json:"y"`
}

func manualMarshal(p Point) []byte {
    buf := make([]byte, 0, 32)
    buf = append(buf, `{"x":`...)
    buf = strconv.AppendInt(buf, int64(p.X), 10)
    buf = append(buf, `,"y":`...)
    buf = strconv.AppendInt(buf, int64(p.Y), 10)
    buf = append(buf, '}')
    return buf
}
BenchmarkJSONMarshal-10      14751967    81.79 ns/op    32 B/op    2 allocs/op
BenchmarkManualMarshal-10    64573988    18.30 ns/op    32 B/op    1 allocs/op

json.Marshal chậm hơn ~4.5 lần (81.79 / 18.30) cho cùng 1 struct 2 field int — chênh lệch hoàn toàn tới từ chi phí reflection (duyệt field, đọc tag, dispatch theo kiểu dữ liệu tại runtime), vì cả 2 cách đều cấp phát đúng 32 byte cho output. Đây là “giá” phải trả cho tính tổng quát — thư viện JSON dựa trên code generation (biết trước cấu trúc tại compile-time) tránh được chi phí này, đổi lại phải chạy 1 bước sinh code trước khi build.

Struct tag: option thật, hiệu ứng thật

type User struct {
    Name     string `json:"name"`
    Email    string `json:"email,omitempty"`
    Age      int    `json:"age,omitempty"`
    Password string `json:"-"`
}
Đầy đủ field: {"name":"An","email":"an@example.com","age":30}
Email/Age rỗng (omitempty): {"name":"Binh"}

omitempty bỏ hẳn field khỏi output khi giá trị là zero value của kiểu đó ("" cho string, 0 cho int) — thấy rõ ở User{Name: "Binh"}, cả email lẫn age biến mất hoàn toàn khỏi JSON thay vì xuất hiện với giá trị rỗng. Password string \json:"-"`` không bao giờ xuất hiện trong output dù có giá trị — cách chuẩn để đảm bảo dữ liệu nhạy cảm không vô tình lọt ra ngoài qua API response.

MarshalJSON/UnmarshalJSON tuỳ biến: enum dạng string

type Status int
const (
    StatusPending Status = iota
    StatusActive
    StatusDone
)

func (s Status) MarshalJSON() ([]byte, error) {
    return []byte(`"` + s.String() + `"`), nil
}

func (s *Status) UnmarshalJSON(data []byte) error {
    switch strings.Trim(string(data), `"`) {
    case "pending": *s = StatusPending
    case "active":  *s = StatusActive
    case "done":    *s = StatusDone
    default: return fmt.Errorf("status không hợp lệ: %s", string(data))
    }
    return nil
}
Marshal (Status thành chuỗi thay vì số): {"name":"Viết bài","status":"active"}
Unmarshal ngược lại: {Name:Đọc bài Status:done} (Status int thật = 2)

Status bên trong vẫn là int (tiết kiệm bộ nhớ, so sánh nhanh), nhưng khi encode/decode qua JSON hiển thị dưới dạng chuỗi dễ đọc ("active" thay vì 1) — API dễ dùng hơn cho client bên ngoài mà không đổi cách biểu diễn nội bộ. json.Marshal/Unmarshal tự động gọi 2 method này nếu type implement json.Marshaler/json.Unmarshaler, không cần cấu hình gì thêm.

Streaming: Decoder giảm bộ nhớ đỉnh ~3.9 lần so với Unmarshal

json.Marshal/Unmarshal load toàn bộ dữ liệu vào bộ nhớ cùng lúc. json.NewDecoder(r).Decode(&v) xử lý qua io.Reader (liên hệ bài 03) — có thể xử lý từng phần tử rồi bỏ đi ngay, không cần giữ hết trong RAM:

// Cách 1: load hết vào 1 slice
var records []Record
json.Unmarshal(data, &records)

// Cách 2: streaming, xử lý và bỏ từng record 1
dec := json.NewDecoder(bytes.NewReader(data))
dec.Token() // '['
for dec.More() {
    var r Record
    dec.Decode(&r)
    // xử lý r ở đây rồi để nó bị GC, không giữ lại
}
Kích thước JSON: 8377781 byte

Unmarshal: HeapAlloc tăng 11596232 bytes | số record: 100000
Decoder streaming: HeapAlloc tăng 2965064 bytes | số record xử lý: 100000

Cùng xử lý đúng 100.000 record từ 1 file JSON ~8MB: Unmarshal vào 1 slice tốn 11.6MB heap (giữ toàn bộ 100.000 struct cùng lúc); streaming qua Decoder chỉ tốn ~3MB — ít hơn ~3.9 lần — vì mỗi record sau khi xử lý được phép trở thành rác ngay, không tích luỹ. Khác biệt càng lớn khi dữ liệu càng lớn: Unmarshal luôn cần đủ RAM chứa toàn bộ kết quả, Decoder chỉ cần đủ cho 1 phần tử tại 1 thời điểm.

main.go gộp 3 demo (struct tag, custom Marshal/Unmarshal, streaming Decoder). reflectcost_test.go chứa 4 benchmark: json.Marshal vs viết tay, và struct phẳng vs lồng sâu — số liệu cho phần sau:

BenchmarkMarshalFlat-10       8472957    142.4 ns/op     80 B/op    2 allocs/op
BenchmarkMarshalNested-10     1839525    658.2 ns/op    400 B/op    7 allocs/op

Struct lồng sâu (slice, map, struct lồng nhau nhiều tầng) chậm hơn ~4.6 lần so với struct phẳng cùng ~5 field — chi phí reflection tăng theo độ phức tạp của kiểu dữ liệu, không chỉ theo số byte output cuối cùng.

Tổng kết & bài tiếp theo

encoding/json đánh đổi tốc độ lấy tính tổng quát: reflection khiến Marshal chậm hơn code viết tay ~4.5 lần cho struct đơn giản, và chi phí tăng thêm khi struct càng lồng sâu. Struct tag (omitempty, -) kiểm soát chính xác output; MarshalJSON/UnmarshalJSON cho phép tuỳ biến hoàn toàn cách 1 type được biểu diễn. Với dữ liệu lớn, json.NewDecoder streaming giữ bộ nhớ đỉnh thấp hơn hẳn Unmarshal load toàn bộ.
