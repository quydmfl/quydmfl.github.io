Mở đầu series homelab Kubernetes: kind (Kubernetes IN Docker) — cách nhanh nhất để có 1 cluster Kubernetes thật chạy ngay trên máy local, không cần cloud, không cần VM nặng nề. Cluster tạo ở bài này sẽ dùng xuyên suốt các bài tiếp theo.

kind là gì, vì sao không phải minikube/k3s

kind chạy mỗi “node” Kubernetes (control-plane, worker) dưới dạng 1 container Docker duy nhất — không phải VM. So với 2 lựa chọn phổ biến khác cho local dev:

  • minikube: thường dùng VM (hoặc driver Docker/container tương tự kind) — nặng hơn nếu chọn driver VM
  • k3s: bản Kubernetes rút gọn (thay etcd bằng SQLite mặc định, bỏ vài component), cài trực tiếp lên máy/VM — nhẹ nhưng không hoàn toàn giống Kubernetes upstream
  • kind: dùng đúng Kubernetes upstream đầy đủ (không rút gọn gì), tạo/huỷ cluster trong vài chục giây, phù hợp nhất cho dev/test local muốn hành vi giống production thật

Kiến trúc thật: 1 node = 1 container Docker

Tạo thử 1 cluster đơn giản nhất để xem tận mắt:

kind create cluster --name homelab-demo
Creating cluster "homelab-demo" ...
 ✓ Ensuring node image (kindest/node:v1.33.1) 🖼
 ✓ Preparing nodes 📦
 ✓ Writing configuration 📜
 ✓ Starting control-plane 🕹️
 ✓ Installing CNI 🔌
 ✓ Installing StorageClass 💾
Set kubectl context to "kind-homelab-demo"
docker ps --filter "label=io.x-k8s.kind.cluster=homelab-demo"
NAMES                        IMAGE                  STATUS          PORTS
homelab-demo-control-plane   kindest/node:v1.33.1   Up 18 seconds   127.0.0.1:50057->6443/tcp

Đúng 1 container Docker — đó là toàn bộ “cluster” 1 node. Vào bên trong xem thật:

docker exec homelab-demo-control-plane ps aux
root   499  kube-scheduler --authentication-kubeconfig=/etc/kubernetes/scheduler.conf ...
root   543  kube-apiserver --advertise-address=172.19.0.2 --secure-port=6443 ...
root   550  kube-controller-manager --cluster-cidr=10.244.0.0/16 ...
root   617  etcd --advertise-client-urls=https://172.19.0.2:2379 ...
root   668  /usr/bin/kubelet --container-runtime-endpoint=unix:///run/containerd/containerd.sock ...
root   104  /usr/local/bin/containerd

Toàn bộ control plane — kube-apiserver, kube-scheduler, kube-controller-manager, etcd — chạy như process thường bên trong đúng 1 container, cùng với kubelet và containerd của chính nó. kubelet bên trong container này lại tiếp tục dùng containerd để chạy các container con (Pod) — 1 lớp lồng container-trong-container. Đây chính là “phép màu” của kind: đóng gói cả 1 cluster Kubernetes hoàn chỉnh vào 1 (hoặc vài) container Docker bình thường.

Cluster nhiều node: khớp chính xác giữa Docker và kubectl

Xoá cluster demo, tạo lại với file cấu hình khai báo rõ số node:

# kind-config.yaml
kind: Cluster
apiVersion: kind.x-k8s.io/v1alpha4
nodes:
  - role: control-plane
  - role: worker
  - role: worker
kind create cluster --name homelab --config kind-config.yaml
 • Preparing nodes 📦 📦 📦   ...
 ✓ Preparing nodes 📦 📦 📦
 ...
 • Joining worker nodes 🚜  ...
 ✓ Joining worker nodes 🚜

3 emoji 📦 — đúng 3 node sẽ tạo. Xác nhận song song ở cả 2 tầng, Docker và Kubernetes:

docker ps --filter "label=io.x-k8s.kind.cluster=homelab" --format "table {{.Names}}\t{{.Status}}"
NAMES                   STATUS
homelab-worker2         Up 28 seconds
homelab-control-plane   Up 28 seconds
homelab-worker          Up 28 seconds
kubectl get nodes
NAME                    STATUS     ROLES           AGE   VERSION
homelab-control-plane   Ready      control-plane   21s   v1.33.1
homelab-worker          NotReady   <none>          7s    v1.33.1
homelab-worker2         NotReady   <none>          7s    v1.33.1

3 container Docker, khớp đúng 3 node Kubernetes. Chú ý 2 worker báo NotReady ngay sau khi tạo — CNI (Container Network Interface, phụ trách cấp IP cho Pod) cần vài giây để khởi động trên từng node. Kiểm tra lại sau ~10 giây:

kubectl get nodes
NAME                    STATUS   ROLES           AGE   VERSION
homelab-control-plane   Ready    control-plane   39s   v1.33.1
homelab-worker          Ready    <none>          25s   v1.33.1
homelab-worker2         Ready    <none>          25s   v1.33.1

Cả 3 node Ready — cluster sẵn sàng nhận Pod thật.

kubeconfig: kind tự động cấu hình, không cần tay

kind get clusters
homelab
kubectl config get-contexts
CURRENT   NAME           CLUSTER        AUTHINFO       NAMESPACE
*         kind-homelab   kind-homelab   kind-homelab

kind create cluster tự động ghi 1 context mới (kind-<tên-cluster>) vào ~/.kube/config và chuyển luôn context hiện tại sang đó (dấu *) — không cần copy/export kubeconfig tay như nhiều cách setup cluster khác.

kubectl config view --minify
apiVersion: v1
clusters:
- cluster:
    certificate-authority-data: DATA+OMITTED
    server: https://127.0.0.1:50073
  name: kind-homelab
current-context: kind-homelab

server: https://127.0.0.1:50073 — kubectl nói chuyện với API server qua đúng port Docker đã map ra host (khớp cột PORTS ở lệnh docker ps phía trên, chỉ khác số port ngẫu nhiên mỗi lần tạo cluster).

kubectl cơ bản: get, describe, logs, exec

Toàn bộ hệ thống Kubernetes (CoreDNS, kube-proxy…) cũng chỉ là Pod chạy trong namespace kube-system — dùng chính chúng để luyện kubectl:

kubectl get pods -n kube-system
NAME                                            READY   STATUS    RESTARTS   AGE
coredns-674b8bbfcf-jfs2v                        1/1     Running   0          22s
coredns-674b8bbfcf-vbzsl                        1/1     Running   0          22s
etcd-homelab-control-plane                      1/1     Running   0          28s
kindnet-49wjh                                   1/1     Running   0          20s
kube-apiserver-homelab-control-plane            1/1     Running   0          27s
kube-proxy-87kz2                                1/1     Running   0          20s
kubectl logs -n kube-system coredns-674b8bbfcf-jfs2v --tail=3
CoreDNS-1.12.0
linux/arm64, go1.23.3, 51e11f1

kubectl exec vào image tối giản (kiểu distroless — liên hệ Go series, Performance & Production bài 06) như coredns sẽ báo lỗi executable file not found cho hầu hết lệnh — tạo 1 Pod đầy đủ hơn để luyện exec:

kubectl run busybox-test --image=busybox:1.36 --restart=Never -- sleep 3600
kubectl exec busybox-test -- hostname
kubectl exec busybox-test -- cat /etc/resolv.conf
busybox-test
search default.svc.cluster.local svc.cluster.local cluster.local
nameserver 10.96.0.10
options ndots:5

nameserver 10.96.0.10 — đúng ClusterIP của Service kube-dns (CoreDNS) mà mọi Pod tự động dùng để phân giải tên nội bộ — nền tảng cho DNS service-to-service sẽ dùng ở các bài sau.

Port mapping: cầu nối từ máy host vào cluster

kind mặc định không expose gì ra host ngoài API server — muốn máy host truy cập được service chạy trong cluster (ví dụ port 80/443 cho Ingress ở bài 07), cần khai báo extraPortMappings:

kind: Cluster
apiVersion: kind.x-k8s.io/v1alpha4
nodes:
  - role: control-plane
    extraPortMappings:
      - containerPort: 80
        hostPort: 8080
        protocol: TCP
      - containerPort: 443
        hostPort: 8443
        protocol: TCP
  - role: worker
  - role: worker
docker ps --filter "name=homelab-control-plane" --format "table {{.Names}}\t{{.Ports}}"
NAMES                   PORTS
homelab-control-plane   0.0.0.0:8080->80/tcp, 0.0.0.0:8443->443/tcp, 127.0.0.1:50073->6443/tcp

8080/8443 trên máy host giờ trỏ thẳng vào port 80/443 của container node — khác hoàn toàn với cluster cloud thật (nơi có LoadBalancer type Service tự cấp IP public). Trên kind, port mapping khai báo lúc tạo cluster là cách duy nhất để mở “cửa” từ ngoài vào — sẽ dùng lại chính cấu hình này khi cài Ingress Controller ở bài 07.

Tự dựng lại cluster này

kind create cluster --name homelab --config kind-config.yaml
kubectl get nodes
kubectl cluster-info

Cluster homelab (3 node, port mapping 8080/8443) sẽ được dùng tiếp ở mọi bài sau — không xoá sau khi đọc xong bài này.

Tổng kết & bài tiếp theo

kind chạy mỗi node Kubernetes là 1 container Docker — xác nhận trực tiếp qua docker ps/docker exec, khớp 1:1 với kubectl get nodes. kind tự động cấu hình kubeconfig, không cần thao tác tay. Port mapping khai báo lúc tạo cluster là cách duy nhất để truy cập từ máy host vào service chạy trong cluster.
