Bài 01 có 1 cluster 3 node chạy. Bài này tổ chức nó thành nhiều “khu vực” logic tách biệt — nền tảng cho việc deploy nhiều service (dev/staging, hoặc nhiều app khác nhau) trong cùng 1 cluster homelab mà không dẫm chân nhau.

Namespace là gì, ranh giới thật của nó

Namespace không cô lập network/CPU/RAM theo mặc định — chỉ là ranh giới đặt tên (naming scope) cho phần lớn resource Kubernetes. Tạo 2 namespace và deploy cùng tên Pod ở cả 2 để xác nhận:

kubectl create namespace dev
kubectl create namespace staging
namespace/dev created
namespace/staging created
kubectl run app --image=nginx:1.27-alpine -n dev
kubectl run app --image=nginx:1.27-alpine -n staging
pod/app created
pod/app created
kubectl get pod app -n dev -o wide
kubectl get pod app -n staging -o wide
NAME   READY   STATUS    RESTARTS   AGE   IP           NODE
app    1/1     Running   0          24s   10.244.1.3   homelab-worker
NAME   READY   STATUS    RESTARTS   AGE   IP           NODE
app    1/1     Running   0          24s   10.244.2.2   homelab-worker2

2 Pod cùng tên app, chạy song song, không đụng độ — Kubernetes scheduler còn tự đặt chúng lên 2 worker node khác nhau (homelab-worker vs homelab-worker2), mỗi node có dải IP Pod riêng (10.244.1.x vs 10.244.2.x). Xoá Pod ở dev để xác nhận staging không bị ảnh hưởng:

kubectl delete pod app -n dev
kubectl get pod app -n staging
pod "app" deleted from dev namespace
NAME   READY   STATUS    RESTARTS   AGE
app    1/1     Running   0          25s

Pod ở staging vẫn còn nguyên — namespace là ranh giới thật cho các thao tác get/delete/apply không chỉ định rõ namespace khác.

ResourceQuota: giới hạn tài nguyên theo namespace — lỗi thật khi vượt

Trên homelab, tài nguyên máy thật hữu hạn (khác cloud có thể scale gần như vô hạn) — ResourceQuota đặt trần cho 1 namespace:

apiVersion: v1
kind: ResourceQuota
metadata:
  name: dev-quota
  namespace: dev
spec:
  hard:
    requests.cpu: "500m"
    requests.memory: "512Mi"
    limits.cpu: "1"
    limits.memory: "1Gi"
    pods: "3"
kubectl apply -f resourcequota.yaml
kubectl describe resourcequota dev-quota -n dev
Resource         Used  Hard
--------         ----  ----
limits.cpu       0     1
limits.memory    0     1Gi
pods             0     3
requests.cpu     0     500m
requests.memory  0     512Mi

Thử tạo Pod không khai báo resources — bị chặn ngay:

kubectl run noquota-test --image=nginx:1.27-alpine -n dev
Error from server (Forbidden): pods "noquota-test" is forbidden: failed quota: dev-quota: must specify limits.cpu for: noquota-test; limits.memory for: noquota-test; requests.cpu for: noquota-test; requests.memory for: noquota-test

Khi namespace đã có ResourceQuota áp lên cpu/memory, mọi Pod trong namespace đó buộc phải khai báo resources.requests/limits tường minh — không có gì để Kubernetes tự suy ra trần nào áp dụng. Thử Pod khai báo nhưng vượt quota:

resources:
  requests:
    cpu: "800m"   # quota chỉ cho phép tổng 500m
    memory: "256Mi"
  limits:
    cpu: "800m"
    memory: "256Mi"
Error from server (Forbidden): pods "over-quota" is forbidden: exceeded quota: dev-quota, requested: requests.cpu=800m, used: requests.cpu=0, limited: requests.cpu=500m

Thông báo lỗi nói rõ chính xác: đang yêu cầu 800m, quota cho phép tối đa 500m. Pod khai báo đúng trong quota tạo thành công và quota tự cập nhật số đã dùng:

kubectl get resourcequota dev-quota -n dev
NAME        REQUEST                                                            LIMIT
dev-quota   pods: 1/3, requests.cpu: 200m/500m, requests.memory: 128Mi/512Mi   limits.cpu: 300m/1, limits.memory: 256Mi/1Gi

LimitRange: giá trị mặc định khi không khai báo resources

Không phải lúc nào cũng muốn buộc mọi Pod khai báo resources (như ResourceQuota ở trên) — LimitRange áp giá trị mặc định cho namespace, Pod không khai báo gì vẫn tự nhận đúng giá trị:

kubectl delete resourcequota dev-quota -n dev   # bỏ quota cũ để demo LimitRange riêng
apiVersion: v1
kind: LimitRange
metadata:
  name: dev-limits
  namespace: dev
spec:
  limits:
    - type: Container
      default:          # limits mặc định nếu Pod không khai báo
        cpu: "250m"
        memory: "128Mi"
      defaultRequest:    # requests mặc định nếu Pod không khai báo
        cpu: "100m"
        memory: "64Mi"
kubectl apply -f limitrange.yaml
kubectl run limitrange-test --image=nginx:1.27-alpine -n dev
kubectl get pod limitrange-test -n dev -o jsonpath='{.spec.containers[0].resources}'
{
    "limits": {"cpu": "250m", "memory": "128Mi"},
    "requests": {"cpu": "100m", "memory": "64Mi"}
}

Pod tạo ra không khai báo bất kỳ resource nào trong lệnh kubectl run, nhưng API server tự động điền đúng 4 giá trị từ LimitRange — kiểm chứng bằng cách đọc lại chính spec Pod sau khi tạo, không phải suy đoán.

kubectl context: tránh gõ -n mọi lệnh

kubectl get pods   # không set namespace -- luôn query "default"
No resources found in default namespace.
kubectl config set-context --current --namespace=dev
kubectl get pods
Context "kind-homelab" modified.
No resources found in dev namespace.
kubectl config set-context --current --namespace=staging
kubectl get pods
Context "kind-homelab" modified.
NAME   READY   STATUS    RESTARTS   AGE
app    1/1     Running   0          86s

kubectl get pods (không -n) trả về kết quả khác nhau tuỳ namespace đang set trong context hiện tại — AGE: 86s xác nhận đây đúng là Pod app đã tạo từ đầu bài, không phải tạo mới. Xác nhận namespace đang lưu trong context:

kubectl config view --minify | grep namespace
    namespace: staging

Kỹ thuật này đặc biệt hữu ích khi làm việc với nhiều namespace liên tục — đặt context đúng 1 lần, mọi lệnh sau đó tự áp dụng namespace đó cho tới khi đổi lại.

Tự chạy lại demo

kubectl create namespace dev
kubectl create namespace staging
kubectl apply -f limitrange.yaml
kubectl config set-context --current --namespace=dev

resourcequota.yaml, pod-over-quota.yaml, pod-within-quota.yaml, limitrange.yaml đi kèm bài viết — chạy đúng thứ tự trong bài để tái hiện từng bước.

Tổng kết & bài tiếp theo

Namespace là ranh giới đặt tên, không tự cô lập tài nguyên — cần ResourceQuota (trần cứng theo namespace, báo lỗi rõ khi vượt) và LimitRange (giá trị mặc định khi Pod không khai báo) để kiểm soát thật. kubectl config set-context --current --namespace=<ns> giúp làm việc với 1 namespace liên tục mà không cần gõ -n mỗi lệnh.
