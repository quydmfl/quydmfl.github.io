Bài 03 viết tay Deployment/Service/Ingress. Bài này đóng gói chính xác những manifest đó thành 1 Helm chart — công cụ package/template hoá phổ biến nhất cho Kubernetes.

Cấu trúc 1 chart: Chart.yaml, values.yaml, templates/

webapp/
├── Chart.yaml
├── values.yaml
└── templates/
    ├── deployment.yaml
    ├── service.yaml
    └── ingress.yaml

Chart.yaml chỉ chứa metadata (tên, version):

apiVersion: v2
name: webapp
description: Chart demo cho series Homelab Kubernetes
type: application
version: 0.1.0
appVersion: "1.0.0"

values.yaml — giá trị mặc định, tham số hoá đúng những gì đã hardcode ở bài 03:

replicaCount: 3
image:
  repository: nginxdemos/hello
  tag: plain-text
resources:
  requests: {cpu: 50m, memory: 32Mi}
  limits: {cpu: 100m, memory: 64Mi}
service:
  port: 80
ingress:
  enabled: false
  host: web-app.homelab.local

Template dùng cú pháp Go template, {{ .Values.xxx }} lấy giá trị từ values.yaml:

# templates/deployment.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: {{ .Release.Name }}-webapp
spec:
  replicas: {{ .Values.replicaCount }}
  template:
    spec:
      containers:
        - name: webapp
          image: "{{ .Values.image.repository }}:{{ .Values.image.tag }}"
          resources:
            {{- toYaml .Values.resources | nindent 12 }}

{{ .Release.Name }} — biến đặc biệt Helm tự inject, là tên release (đặt lúc helm install), cho phép deploy nhiều bản của cùng 1 chart với tên khác nhau, không đụng resource name.

helm lint & helm template: kiểm tra trước khi chạm cluster

helm lint webapp
==> Linting webapp
[INFO] Chart.yaml: icon is recommended
1 chart(s) linted, 0 chart(s) failed

helm template render ra YAML thật mà không áp dụng gì vào cluster — cách an toàn để xem trước:

helm template myapp webapp
# Source: webapp/templates/service.yaml
apiVersion: v1
kind: Service
metadata:
  name: myapp-webapp
---
# Source: webapp/templates/deployment.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: myapp-webapp
spec:
  replicas: 3
  ...

Chú ý: templates/ingress.yaml không xuất hiện trong output — chart có logic {{- if .Values.ingress.enabled }}, mặc định false nên template tự bỏ qua toàn bộ resource đó. Đổi giá trị qua --set, xem output thay đổi ngay:

helm template myapp webapp --set replicaCount=5 --set ingress.enabled=true
kind: Service
kind: Deployment
  replicas: 5
kind: Ingress
    - host: web-app.homelab.local

replicas: 5 (đổi từ mặc định 3) và kind: Ingress giờ xuất hiện — chỉ đổi 2 tham số, không sửa file nào.

helm install: tạo 1 release thật

kubectl create namespace helm-demo
helm install myapp webapp -n helm-demo
NAME: myapp
LAST DEPLOYED: Sat Sep 12 13:25:32 2026
NAMESPACE: helm-demo
STATUS: deployed
REVISION: 1
helm list -n helm-demo
NAME 	NAMESPACE	REVISION	STATUS  	CHART       	APP VERSION
myapp	helm-demo	1       	deployed	webapp-0.1.0	1.0.0

Khác biệt cốt lõi so với kubectl apply ở bài 03: Helm theo dõi release — 1 đơn vị có tên, có lịch sử revision, không chỉ là tập YAML rời rạc.

helm upgrade: đổi giá trị, tạo revision mới

helm upgrade myapp webapp -n helm-demo --set image.tag=latest
Release "myapp" has been upgraded. Happy Helming!
REVISION: 2
kubectl get pods -n helm-demo -o jsonpath='{range .items[*]}{.metadata.name}{"\t"}{.spec.containers[0].image}{"\n"}{end}'
myapp-webapp-8575fdf887-74gfx	nginxdemos/hello:latest
myapp-webapp-8575fdf887-c4vzg	nginxdemos/hello:latest
myapp-webapp-8575fdf887-p94sp	nginxdemos/hello:latest

Cả 3 Pod đổi sang image latest — helm upgrade bên dưới vẫn dùng đúng cơ chế rolling update của Deployment đã học ở bài 03, chỉ khác ở tầng gọi lệnh.

helm rollback: quay lại revision cũ — tạo thêm 1 revision mới, không “xoá lịch sử”

helm rollback myapp 1 -n helm-demo
Rollback was a success! Happy Helming!
helm history myapp -n helm-demo
REVISION	STATUS    	CHART       	DESCRIPTION
1       	superseded	webapp-0.1.0	Install complete
2       	superseded	webapp-0.1.0	Upgrade complete
3       	deployed  	webapp-0.1.0	Rollback to 1

Điều dễ hiểu nhầm: rollback không quay kim đồng hồ về revision 1 — nó tạo revision 3 mới, có nội dung giống revision 1. Lịch sử luôn chỉ tiến, không lùi — helm history vẫn thấy đủ cả 3 lần, hữu ích khi cần biết “đã từng đổi gì, khi nào”.

kubectl get pods -n helm-demo -o jsonpath='{range .items[*]}{.metadata.name}{"\t"}{.spec.containers[0].image}{"\n"}{end}'
myapp-webapp-5df98c8694-j6kgf	nginxdemos/hello:plain-text
myapp-webapp-5df98c8694-tz2wf	nginxdemos/hello:plain-text
myapp-webapp-5df98c8694-v9pqm	nginxdemos/hello:plain-text

Image quay lại đúng plain-text như revision 1.

values override: 1 chart, nhiều môi trường

Tạo 2 file values riêng cho dev/prod:

# values-dev.yaml
replicaCount: 1
image:
  tag: plain-text
# values-prod.yaml
replicaCount: 3
image:
  tag: latest
ingress:
  enabled: true
  host: web-app.homelab.local
helm install myapp-dev webapp -n helm-demo -f values-dev.yaml
helm install myapp-prod webapp -n helm-demo -f values-prod.yaml
kubectl get deploy,ingress -n helm-demo
NAME                                READY   UP-TO-DATE   AVAILABLE
deployment.apps/myapp-dev-webapp    1/1     1            1
deployment.apps/myapp-prod-webapp   3/3     3            3

NAME                                          CLASS    HOSTS
ingress.networking.k8s.io/myapp-prod-webapp   <none>   web-app.homelab.local

Cùng 1 chart, myapp-dev chạy đúng 1 replica (theo values-dev.yaml), myapp-prod chạy 3 replica và tự tạo thêm Ingress (vì values-prod.yaml đặt ingress.enabled: true) — không sửa bất kỳ file template nào, chỉ đổi file values truyền vào lúc install.

Tự chạy lại demo

cd webapp
helm lint .
helm template myapp .
helm install myapp . -n helm-demo
helm upgrade myapp . -n helm-demo --set image.tag=latest
helm rollback myapp 1 -n helm-demo
helm install myapp-dev . -n helm-demo -f values-dev.yaml
helm install myapp-prod . -n helm-demo -f values-prod.yaml

Toàn bộ chart (Chart.yaml, values.yaml, values-dev.yaml, values-prod.yaml, templates/) đi kèm bài viết trong thư mục webapp/.

Tổng kết & bài tiếp theo

Helm đóng gói manifest thành chart tham số hoá qua values.yaml — helm template xem trước an toàn, helm install/upgrade tạo và cập nhật 1 release có lịch sử revision thật (helm history), rollback tạo revision mới thay vì tua lại thời gian. 1 chart, nhiều file values, deploy được nhiều “phiên bản” cấu hình khác nhau (dev/prod) mà không sửa template.
