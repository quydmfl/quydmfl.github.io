Kết hợp bài 04 (Helm chart) và bài 05 (Terraform quản lý cluster): dùng helm provider của Terraform để chính Terraform gọi helm install/upgrade thay vì CLI thủ công — 1 state duy nhất mô tả toàn bộ trạng thái mong muốn của cluster.

provider “helm”: cầu nối Terraform → Helm

terraform {
  required_providers {
    kubernetes = { source = "hashicorp/kubernetes", version = "~> 2.31" }
    helm       = { source = "hashicorp/helm",       version = "~> 2.15" }
  }
}

provider "kubernetes" {
  config_path    = "~/.kube/config"
  config_context = "kind-homelab"
}

provider "helm" {
  kubernetes {
    config_path    = "~/.kube/config"
    config_context = "kind-homelab"
  }
}

Chú ý cú pháp: helm provider dùng block kubernetes { ... } (không có dấu =) — khác với resource khác thường dùng = {}. Nhầm cú pháp này báo lỗi Unsupported argument ngay lúc terraform validate.

Deploy chart từ bài 04 qua Terraform

resource "kubernetes_namespace" "app" {
  metadata {
    name = "tf-helm-demo"
  }
}

resource "helm_release" "webapp" {
  name      = "myapp"
  namespace = kubernetes_namespace.app.metadata[0].name
  chart     = "./webapp"

  values = [
    file("./webapp/values-dev.yaml")
  ]

  depends_on = [kubernetes_namespace.app]
}
terraform apply -auto-approve
kubernetes_namespace.app: Creating...
kubernetes_namespace.app: Creation complete after 0s [id=tf-helm-demo]
helm_release.webapp: Creating...
helm_release.webapp: Creation complete after 2s [id=myapp]

Apply complete! Resources: 2 added, 0 changed, 0 destroyed.

Xác nhận bằng chính helm CLI — release này không khác gì 1 lần helm install chạy tay:

helm list -n tf-helm-demo
kubectl get pods -n tf-helm-demo -o jsonpath='{.items[0].spec.containers[0].image}'
NAME 	NAMESPACE   	REVISION	STATUS  	CHART       	APP VERSION
myapp	tf-helm-demo	1       	deployed	webapp-0.1.0	1.0.0

nginxdemos/hello:plain-text

Đúng values-dev.yaml (1 replica, image plain-text) đã dùng ở bài 04.

Đổi values qua Terraform: plan phân biệt rõ “sửa” và “tạo mới”

Đổi file values sang values-prod.yaml:

resource "helm_release" "webapp" {
  # ...
  values = [
    file("./webapp/values-prod.yaml")   # đổi từ values-dev.yaml
  ]
}
terraform plan
      ~ values                     = [
          ~ <<-EOT
              - replicaCount: 1
              + replicaCount: 3
                image:
              -   tag: plain-text
              +   tag: latest
              + ingress:
              +   enabled: true
              +   host: web-app.homelab.local
            EOT,
        ]

Plan: 0 to add, 1 to change, 0 to destroy.

1 to change, không phải 1 to destroy, 1 to add — Terraform biết đây là 1 lần sửa release đã tồn tại (tương ứng helm upgrade), không phải xoá tạo lại. Diff hiển thị rõ chính xác dòng nào trong values thay đổi trước khi chạm cluster.

terraform apply -auto-approve
helm history myapp -n tf-helm-demo
helm_release.webapp: Modifying... [id=myapp]
helm_release.webapp: Modifications complete after 6s [id=myapp]

REVISION	STATUS    	DESCRIPTION
1       	superseded	Install complete
2       	deployed  	Upgrade complete

helm history xác nhận: Terraform “Modifying” thật ra là helm upgrade thật đứng sau — REVISION 2 ghi đúng Upgrade complete, không phải cài lại từ đầu. kubectl get deploy,ingress xác nhận thêm: 3 replica và Ingress (myapp-webapp) đã xuất hiện đúng theo values-prod.yaml.

Phụ thuộc giữa resource: thiếu nó thì lỗi thật, race condition thật

Outline gốc nói “cần depends_on” — thử bỏ hẳn liên kết giữa 2 resource để xem hậu quả thật chứ không phải suy đoán. Namespace hardcode thẳng chuỗi ký tự, không tham chiếu kubernetes_namespace, không depends_on:

resource "kubernetes_namespace" "app" {
  metadata { name = "tf-helm-demo" }
}

resource "helm_release" "webapp_nodep" {
  name      = "myapp2"
  namespace = "tf-helm-demo2"   # chuỗi cứng, không liên quan gì tới resource trên
  chart     = "./webapp"
}
terraform apply -auto-approve
kubernetes_namespace.app: Creating...
helm_release.webapp_nodep: Creating...
kubernetes_namespace.app: Creation complete after 0s [id=tf-helm-demo]

Error: create: failed to create: namespaces "tf-helm-demo2" not found

Race condition thật: log cho thấy Terraform bắt đầu tạo cả 2 resource cùng lúc (Creating... xuất hiện liên tiếp không chờ nhau) — vì không có cạnh phụ thuộc nào nối chúng, Terraform coi 2 resource độc lập, chạy song song để tối ưu tốc độ. helm_release nhắm tới namespace tf-helm-demo2 (khác cả tên với namespace vừa tạo — lỗi đặt tên cố ý để demo rõ ràng) chưa từng được tạo bởi bất kỳ resource nào, nên thất bại ngay.

Sửa đúng bằng tham chiếu attribute (kubernetes_namespace.app.metadata[0].name, như ở phần trên) — Terraform tự suy ra cạnh phụ thuộc từ chính tham chiếu đó, depends_on tường minh chỉ cần thiết khi 2 resource liên quan nhau nhưng không có tham chiếu attribute nào (ví dụ phụ thuộc theo thứ tự logic, không theo dữ liệu). Áp dụng lại đúng cấu hình có tham chiếu, chạy trên state hoàn toàn sạch:

terraform apply -auto-approve
kubernetes_namespace.app: Creating...
kubernetes_namespace.app: Creation complete after 0s [id=tf-helm-demo]
helm_release.webapp: Creating...
helm_release.webapp: Creation complete after 6s [id=myapp]

Apply complete! Resources: 2 added, 0 changed, 0 destroyed.

Lần này namespace tạo xong hoàn toàn (Creation complete) rồi mới bắt đầu helm_release.webapp: Creating... — đúng thứ tự tuần tự nhờ cạnh phụ thuộc ngầm.

Tự chạy lại demo

cd terraform
terraform init
terraform apply -auto-approve
# đổi values = [file("./webapp/values-prod.yaml")] trong helm-release.tf
terraform plan
terraform apply -auto-approve
terraform destroy -auto-approve

Toàn bộ .tf + chart webapp/ (dùng lại từ bài 04) đi kèm bài viết.

Tổng kết & bài tiếp theo

helm_release resource của Terraform gọi đúng helm install/upgrade/uninstall thật bên dưới — xác nhận được qua helm history/helm list như dùng CLI tay. terraform plan phân biệt rõ sửa (to change) và tạo mới (to add) dựa trên diff giá trị thật. Phụ thuộc giữa resource phải được khai báo (qua tham chiếu attribute, hoặc depends_on khi không có tham chiếu nào) — thiếu nó, Terraform chạy song song và có thể thất bại đúng lúc thứ tự thực tế quan trọng, như đã thấy qua lỗi thật namespaces "tf-helm-demo2" not found.

Bài 07 đi vào Ingress Controller — cài ingress-nginx (cũng có thể quản lý qua chính helm_release vừa học) để route nhiều service qua 1 entrypoint duy nhất, chuẩn bị cho việc expose ra internet ở bài 08.
