Bài 01 liệt kê cây thư mục 4 crate, và kernel là crate nhỏ nhất trong đó — 4 file .rs, không chia domain/application/infrastructure. Nhưng đừng để kích thước đánh lừa: kernel là crate duy nhất mà cả translation lẫn slack_gateway đều phụ thuộc vào, còn bản thân nó không phụ thuộc ngược lại crate nào trong 2 crate đó. Bài này mổ xẻ từng file, xem kernel chứa cái gì và vì sao chỉ chứa đúng chừng đó.

Vì sao cần shared kernel

Bot cần khái niệm “ngôn ngữ” ở 2 chỗ khác hẳn nhau. translation cần biết dịch sang ngôn ngữ nào — người dùng chỉ định ngôn ngữ đích, module dịch nhận vào và gọi LibreTranslate. slack_gateway cần biết ngôn ngữ nào ứng với emoji cờ vừa được react — flag-vn suy ra vi, flag-us suy ra en. Hai chỗ dùng khác nhau, nhưng cùng 1 khái niệm: mã ngôn ngữ ISO 639-1 hợp lệ.

Đặt kiểu này vào translation::domain rồi để slack_gateway import vào là phá vỡ đúng quy tắc đã nói ở bài 01: slack_gateway chỉ được đụng translation::application, không bao giờ đụng phần còn lại — kể cả domain. Đặt vào slack_gateway::domain rồi để translation import ngược lại thì cũng sai y hệt, chỉ đổi chiều. Cả 2 hướng đều tạo phụ thuộc chéo giữa 2 bounded context lẽ ra phải độc lập với nhau.

Giải pháp: kiểu dữ liệu này không thuộc về riêng module nào — nó thuộc về cả 2, nên đặt vào 1 crate riêng mà cả 2 cùng phụ thuộc. Đó là lý do kernel tồn tại. crates/kernel/src/lib.rs:

//! Shared kernel: the small set of types every module is allowed to depend on
//! (config, generic error helpers, cross-module value objects). Keep this crate
//! deliberately tiny — anything module-specific belongs in that module instead.

pub mod config;
pub mod error;
pub mod lang;

pub use config::AppConfig;
pub use lang::LanguageCode;

3 module con, 2 kiểu được re-export thẳng ra root (AppConfig, LanguageCode) để nơi khác gọi kernel::AppConfig thay vì phải gõ đường dẫn đầy đủ kernel::config::AppConfig. Docstring ở đầu file nói thẳng ý đồ thiết kế: đây là danh sách những gì mọi module được phép phụ thuộc — không phải nơi chứa tiện thứ gì cũng nhét vào.

AppConfig::from_env(): load cấu hình 1 lần lúc khởi động

crates/kernel/src/config.rs:

use std::env;

/// Process configuration, loaded once at startup from environment variables
/// (see `.env.example`). Lives in the shared kernel because every module's
/// composition wiring in `crates/app` needs a piece of it.
#[derive(Debug, Clone)]
pub struct AppConfig {
    pub port: u16,
    pub slack_bot_token: String,
    pub slack_signing_secret: String,
    pub libretranslate_url: String,
    pub libretranslate_api_key: Option<String>,
}

#[derive(Debug, thiserror::Error)]
pub enum ConfigError {
    #[error("missing required env var: {0}")]
    Missing(&'static str),
    #[error("invalid value for env var {0}: {1}")]
    Invalid(&'static str, String),
}

impl AppConfig {
    pub fn from_env() -> Result<Self, ConfigError> {
        let port = match env::var("PORT") {
            Ok(v) => v
                .parse::<u16>()
                .map_err(|e| ConfigError::Invalid("PORT", e.to_string()))?,
            Err(_) => 3000,
        };

        Ok(Self {
            port,
            slack_bot_token: require_env("SLACK_BOT_TOKEN")?,
            slack_signing_secret: require_env("SLACK_SIGNING_SECRET")?,
            libretranslate_url: env::var("LIBRETRANSLATE_URL")
                .unwrap_or_else(|_| "http://localhost:5000".to_string()),
            libretranslate_api_key: env::var("LIBRETRANSLATE_API_KEY")
                .ok()
                .filter(|v| !v.is_empty()),
        })
    }
}

fn require_env(key: &'static str) -> Result<String, ConfigError> {
    env::var(key).map_err(|_| ConfigError::Missing(key))
}

AppConfig chỉ được dựng 1 lần, ngay lúc main() khởi động (crates/app — composition root từ bài 01), rồi truyền xuống mọi module cần nó. Đó là lý do nó nằm trong kernel chứ không nằm trong app: bản thân app chỉ nối dây, còn kiểu dữ liệu cấu hình lại cần được cả translation (URL LibreTranslate) lẫn slack_gateway (token, signing secret) nhìn thấy được, thông qua kernel.

ConfigError là 1 enum thiserror với đúng 2 biến thể, ứng với đúng 2 cách 1 biến môi trường có thể sai: Missing — biến không tồn tại, và Invalid — biến tồn tại nhưng parse ra kiểu đích thất bại (ví dụ PORT=abc không parse được thành u16). Attribute #[error("...")] trên từng variant sinh sẵn implementation của trait Display — không phải tự tay viết impl fmt::Display for ConfigError { ... } với match từng nhánh. #[derive(Debug, thiserror::Error)] là công thức chuẩn xuất hiện lặp lại khắp project này cho mọi enum lỗi trong ranh giới module.

require_env là 1 helper riêng, không public, chỉ để tránh lặp lại env::var(key).map_err(|_| ConfigError::Missing(key)) 2 lần cho slack_bot_token và slack_signing_secret. Còn libretranslate_url và libretranslate_api_key không bắt buộc — có giá trị mặc định (localhost:5000) hoặc mặc định là rỗng (None), nên không cần đi qua require_env.

LanguageCode: value object tự validate

crates/kernel/src/lang.rs:

use serde::{Deserialize, Serialize};
use std::fmt;

/// ISO 639-1 language code. A shared value object: both the `translation` and
/// `slack_gateway` modules need "a language", and duplicating it per module
/// (or worse, depending on one another's domain layer) would be worse than
/// a small shared kernel type.
#[derive(Debug, Clone, PartialEq, Eq, Hash, Serialize, Deserialize)]
pub struct LanguageCode(String);

impl LanguageCode {
    pub fn new(code: impl Into<String>) -> Result<Self, InvalidLanguageCode> {
        let code = code.into().to_lowercase();
        if code.len() == 2 && code.chars().all(|c| c.is_ascii_alphabetic()) {
            Ok(Self(code))
        } else {
            Err(InvalidLanguageCode(code))
        }
    }

    pub fn as_str(&self) -> &str {
        &self.0
    }
}

impl fmt::Display for LanguageCode {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        write!(f, "{}", self.0)
    }
}

#[derive(Debug, thiserror::Error)]
#[error("invalid ISO 639-1 language code: {0}")]
pub struct InvalidLanguageCode(String);

Chi tiết dễ bỏ qua nhưng quan trọng nhất ở đây: field String bên trong LanguageCode không có pub. LanguageCode(String) — tuple struct, field ở vị trí 0, không tiền tố pub. Trong Rust, field không pub chỉ truy cập được từ trong chính module khai báo nó (lang.rs). Bên ngoài module này, không có cách nào viết LanguageCode("xyz".to_string()) trực tiếp — trình biên dịch từ chối compile. Cách duy nhất để có 1 giá trị LanguageCode là gọi LanguageCode::new(...), và hàm này validate trước khi trả về Ok.

Đây chính là nguyên tắc “make invalid states unrepresentable” — làm cho trạng thái sai không thể tồn tại trong kiểu dữ liệu, thay vì tồn tại được rồi phải nhớ kiểm tra lại ở mọi nơi dùng đến nó. new() kiểm tra đúng 2 điều kiện: đúng 2 ký tự (code.len() == 2), và cả 2 ký tự đều là chữ cái ASCII (chars().all(|c| c.is_ascii_alphabetic())). Chuỗi qua được cả 2 điều kiện mới trở thành Ok(Self(code)) — còn lại là Err(InvalidLanguageCode(code)).

Hệ quả thực dụng: mọi nơi trong codebase cầm 1 giá trị kiểu LanguageCode — dù đọc từ config, parse từ JSON Slack event, hay nhận qua tham số hàm — đều chắc chắn 100% giá trị đó là mã ISO 639-1 hợp lệ 2 ký tự. Không có hàm nào cần viết lại if code.len() == 2 && ... để kiểm tra phòng hờ, vì không có đường nào để 1 LanguageCode không hợp lệ lọt vào chương trình. Validation xảy ra đúng 1 lần, ở đúng 1 chỗ — biên giới nơi dữ liệu thô (String từ bên ngoài) đi vào hệ thống.

Serialize/Deserialize cho phép LanguageCode serialize thẳng ra JSON dạng chuỗi (ví dụ khi trả response), nhưng #[derive(Deserialize)] ở đây deserialize ngược lại thành String trước rồi bọc trực tiếp vào tuple struct — nó không gọi qua new(), nên về lý thuyết deserialize từ JSON không đi qua validation. Trên thực tế của project này, LanguageCode chỉ được dựng từ input đã qua new() (ví dụ giá trị nhận diện từ emoji, hoặc tham số người dùng nhập), derive(Deserialize) ở đây chủ yếu phục vụ việc lồng LanguageCode bên trong 1 struct lớn hơn cần serialize round-trip nội bộ chứ không phải cổng nhận dữ liệu thô từ bên ngoài — nhưng đây vẫn là 1 khe hở đáng nhớ nếu sau này LanguageCode được deserialize trực tiếp từ 1 request chưa qua kiểm tra.

Verify bằng test thật

crates/kernel/src/lang.rs có sẵn 2 test, chạy trực tiếp trên crate kernel:

cd /path/to/slackbot
cargo test -p kernel -- --test-threads=1
running 2 tests
test lang::tests::accepts_two_letter_codes ... ok
test lang::tests::rejects_anything_else ... ok

test result: ok. 2 passed; 0 failed; 0 ignored; 0 measured; 0 filtered out; finished in 0.00s

accepts_two_letter_codes xác nhận "vi" và "EN" đều hợp lệ — chú ý "EN" viết hoa vẫn qua được, vì new() gọi to_lowercase() trước khi kiểm tra độ dài và ký tự, nên LanguageCode luôn lưu dạng chữ thường bất kể input viết hoa hay thường. rejects_anything_else xác nhận 3 trường hợp sai bị từ chối: "vie" (3 ký tự, sai độ dài), "" (rỗng), và "v1" (có chữ số, không phải toàn chữ cái). 2 test, 2 assertion nhóm theo đúng 2 nhánh của if trong new() — không thừa, không thiếu.

BoxError: chỉ dùng ở rìa hệ thống

crates/kernel/src/error.rs:

/// Type-erased error alias for spots where threading a concrete error type
/// through isn't worth it (e.g. `main`'s top level). Prefer a real `thiserror`
/// enum inside module boundaries — reach for this only at the edges.
pub type BoxError = Box<dyn std::error::Error + Send + Sync + 'static>;

Đúng 1 dòng, nhưng đáng nói vì nó thể hiện rõ khuyến nghị chính của cả codebase này về xử lý lỗi. ConfigError và InvalidLanguageCode ở trên là lỗi cụ thể — enum hoặc struct riêng, biết chính xác lỗi nào có thể xảy ra, người gọi có thể match từng nhánh để xử lý khác nhau. Đó là lựa chọn mặc định trong ranh giới 1 module: dùng thiserror định nghĩa 1 kiểu lỗi riêng cho module đó.

BoxError là ngược lại — lỗi xoá kiểu (type-erased): Box<dyn std::error::Error> che giấu hoàn toàn kiểu lỗi cụ thể bên trong, chỉ còn biết “đây là 1 lỗi nào đó implement trait Error, và nó gửi được qua thread (Send + Sync)”. Cái giá phải trả: người gọi hàm trả về BoxError không thể match để phân biệt lỗi này với lỗi khác, chỉ có thể in ra hoặc propagate tiếp.

Đổi lại là sự tiện lợi ở đúng những chỗ không đáng đầu tư 1 enum lỗi riêng: main() trong crates/app, nơi duy nhất trong toàn bộ chương trình, lỗi từ ConfigError, lỗi khởi tạo HTTP server, lỗi kết nối mạng… đều có thể xảy ra cùng lúc, và tất cả những gì main() cần làm là in lỗi ra rồi thoát với mã lỗi khác 0 — không cần biết chính xác đó là loại lỗi nào để match xử lý riêng. Ngay khi lỗi cần được xử lý khác nhau tuỳ loại — retry lỗi mạng nhưng không retry lỗi cấu hình sai chẳng hạn — BoxError không còn phù hợp nữa, quay lại dùng enum thiserror cụ thể.

Cảnh báo: giữ kernel cực nhỏ

kernel dừng lại ở đúng 3 thứ: cấu hình toàn cục, 1 alias lỗi type-erased dùng ở rìa, và 1 value object dùng chung giữa 2 bounded context. Không có gì khác. Đặc biệt, không có bất cứ thứ gì đặc thù riêng cho translation hay slack_gateway. Kiểu Translation (entity đại diện cho 1 lượt dịch, sẽ gặp ở bài 03) không thuộc về kernel — nó chỉ translation cần, nên nó nằm trong translation::domain. Kiểu đại diện cho 1 Slack event cũng vậy — chỉ slack_gateway cần, nằm trong slack_gateway::domain.

Ranh giới ở đây rất cụ thể, không mơ hồ: 1 kiểu dữ liệu chỉ xứng đáng vào kernel khi từ 2 bounded context độc lập trở lên cùng cần nó, và bản thân kiểu đó không thiên về nghiệp vụ riêng của bên nào. LanguageCode qua được bài kiểm tra này vì “ngôn ngữ” là khái niệm trung lập — không thuộc về nghiệp vụ dịch thuật hay nghiệp vụ Slack, cả 2 chỉ đang mượn cùng 1 khái niệm.

Nếu 1 ngày nào đó kernel phình to — có thêm 5-10 kiểu, có logic nghiệp vụ phức tạp bên trong — đó không phải dấu hiệu kernel đang “trưởng thành”. Đó là dấu hiệu ranh giới giữa các bounded context đang bị nhầm: hoặc có thứ đáng lẽ thuộc về 1 module cụ thể lại bị nhét vào chỗ dùng chung cho tiện, hoặc 2 module lẽ ra nên tách domain riêng lại đang chia sẻ quá nhiều khái niệm nghiệp vụ — nghĩa là ranh giới bounded context đã vẽ sai chỗ ngay từ đầu. kernel càng nhỏ, càng chứng minh 2 module chính của project đủ độc lập với nhau.

Tổng kết & bài tiếp theo

kernel nhỏ vì nó phải nhỏ, không phải vì chưa làm xong. 3 thành phần: AppConfig load 1 lần từ env với ConfigError kiểu thiserror, LanguageCode — value object tự validate ở new(), không có cách nào khác để tạo ra 1 giá trị của nó — và BoxError, dùng đúng ở rìa hệ thống chứ không phải bên trong ranh giới module. Cả 3 tồn tại vì lý do giống nhau: cần dùng chung giữa translation và slack_gateway, hoặc giữa app và mọi module khác.
