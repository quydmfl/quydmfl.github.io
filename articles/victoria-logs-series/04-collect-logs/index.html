Cấu hình Vector ở bài 03 mới chỉ làm một việc: chuyển tiếp nguyên văn log từ Docker sang VictoriaLogs. Đủ để xác nhận pipeline chạy, nhưng chưa đủ để điều tra sự cố — log vẫn là chuỗi text thô, chưa có field nào để filter ngoài container_name/host. Bài này thêm bước transform: parse, làm giàu, và lọc log trước khi ghi.

Anatomy của một event trong Vector

Trước khi viết transform, cần biết chính xác docker_logs source tạo ra event gì. Với mỗi dòng log Docker sinh ra, Vector tạo một event dạng:

{
  "message": "nội dung dòng log gốc",
  "container_name": "vector",
  "container_id": "a1b2c3d4e5f6",
  "image": "timberio/vector:latest-alpine",
  "host": "docker-host-01",
  "stream": "stdout",
  "timestamp": "2026-09-13T08:12:03.441Z",
  "label": { "com.docker.compose.project": "victoria-logs-series" }
}

message luôn là string thô — kể cả khi ứng dụng bên trong container log ra JSON, Docker vẫn coi đó là một dòng text. Đây chính là việc transform cần xử lý: tách nội dung có cấu trúc ra khỏi chuỗi thô đó.

Vector Remap Language (VRL)

Vector dùng VRL — một ngôn ngữ nhỏ, dành riêng cho việc biến đổi observability data — thay vì để người dùng viết plugin bằng Lua/JS như nhiều công cụ khác. VRL có ba đặc điểm đáng nhớ:

  • An toàn kiểu (type-safe) và không có vòng lặp/side-effect ẩn — mỗi transform chạy nhanh, có thể đoán trước hiệu năng, phù hợp chạy trên mọi event với tốc độ cao.
  • Có xử lý lỗi tường minh. Một hàm có thể “fail” (ví dụ parse_json với input không phải JSON) trả về cặp (giá trị, lỗi) — bắt buộc người viết phải quyết định làm gì khi lỗi xảy ra, thay vì để exception rơi tự do và làm rớt cả pipeline.
  • Compile trước khi chạy. Lỗi cú pháp bị bắt ngay lúc Vector khởi động, không đợi đến khi gặp đúng dòng log gây lỗi runtime.

Transform 1: parse và làm giàu (enrich)

transforms:
  enrich:
    type: remap
    inputs:
      - docker_logs
    source: |
      parsed, err = parse_json(.message)
      if err == null && is_object(parsed) {
        . = merge(., object!(parsed))
      }

      .environment = "local"

      if exists(.level) {
        .level = downcase(to_string!(.level))
      }

Đọc từng dòng:

  • parsed, err = parse_json(.message) — thử parse message thành JSON. Vì có thể thất bại (log không phải JSON, ví dụ log của chính Vector), kết quả trả về cặp giá trị: parsed và err. Đây là ví dụ rõ nhất cho cách VRL buộc xử lý lỗi tường minh thay vì crash.
  • if err == null && is_object(parsed) — chỉ merge khi parse thành công và kết quả là object (không phải số/mảng/string trần).
  • . = merge(., object!(parsed)) — merge field của JSON parse được vào event gốc. Từ đây, nếu ứng dụng log ra {"level":"error","user_id":123,"message":"payment failed"}, ba field level, user_id, message (ghi đè field message gốc) sẽ trở thành field độc lập, filter được trực tiếp trong LogsQL — thay vì phải tìm bằng full-text trên chuỗi JSON thô.
  • .environment = "local" — gắn field cố định. Trong bài 07, khi cân nhắc gửi log từ nhiều môi trường về cùng một VictoriaLogs, field này là thứ để phân biệt.
  • Chuẩn hoá level về chữ thường — tránh tình trạng cùng một mức log nhưng viết hoa/thường khác nhau giữa các ứng dụng (ERROR vs error) khiến query LogsQL bỏ sót kết quả.

Transform 2: lọc log rác (drop_noise)

transforms:
  drop_noise:
    type: filter
    inputs:
      - enrich
    condition: |
      !contains!(string!(.message), "GET /health")

Vì Vector đang thu log của chính stack (kể cả Grafana sau này liên tục gọi healthcheck), một phần đáng kể log sinh ra không mang giá trị điều tra sự cố — chỉ là nhiễu. Transform filter giữ lại event khi condition đúng (ở đây: message không chứa "GET /health"), loại bỏ phần còn lại trước khi tốn chi phí lưu trữ trên VictoriaLogs.

Nguyên tắc chung: lọc rác càng gần nguồn càng tốt (ở Vector, trước khi ghi), không lọc bằng cách “cứ ghi hết rồi query loại trừ sau” — cách đó vừa tốn dung lượng lưu trữ, vừa làm chậm mọi query sau này.

Route dữ liệu qua từng bước

Chuỗi transform tạo thành một pipeline tuyến tính:

docker_logs ──▶ enrich ──▶ drop_noise ──▶ (sink) victorialogs

Mỗi transform khai báo inputs trỏ đến bước trước — đây chính là cách Vector cho phép ghép nhiều transform thành pipeline mà không cần một framework xử lý luồng phức tạp. Muốn thêm bước xử lý mới (ví dụ: route log level: error sang một sink cảnh báo riêng ở các bài sau), chỉ cần thêm transform mới với inputs phù hợp — không phải sửa lại các bước đã có.

Áp dụng cấu hình

Copy nội dung file config/vector.yaml đi kèm bài này đè lên file đang mount ở bài 03, sau đó khởi động lại riêng service Vector — không cần đụng đến VictoriaLogs đang chạy:

docker compose restart vector

Kiểm tra kết quả

Cách nhanh nhất để xem transform hoạt động đúng, không cần đợi dữ liệu lên tới VictoriaLogs, là dùng vector tap — xem trực tiếp event đi qua một component bất kỳ trong pipeline đang chạy:

docker compose exec vector vector tap enrich

Lệnh này in ra các event sau khi đi qua transform enrich, giúp xác nhận field mới (environment, các field parse từ JSON) đã xuất hiện trước khi chúng bị lọc hay ghi đi đâu.

Sau đó xác nhận field đã lên tới VictoriaLogs bằng LogsQL API:

curl http://localhost:9428/select/logsql/query -d 'query=environment:local' | head -n 3

Nếu kết quả trả về JSON có field environment — pipeline enrich đã hoạt động đúng.

Tiếp theo

Log giờ đã có field có cấu trúc (level, environment, container_name…) thay vì chỉ là chuỗi thô. Bài 05 sẽ dùng chính những field này để học LogsQL — từ tìm từ khoá đơn giản đến các pipe thống kê nâng cao.
